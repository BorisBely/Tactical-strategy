# Стрельба и отдача (самодостаточный разбор)

Документ описывает **пехотную hitscan-стрельбу** юнита: как выбирается направление пули, как копится отдача и как она меняет **следующий** выстрел. Его можно анализировать **без проекта и без кода**.

Снимок логики: **2026-08-19**. Числа ниже — **дефолты из кода** (поля компонентов). Конкретное оружие / патрон / префаб юнита в инспекторе могут отличаться; формулы при этом те же.

Турель (M2 / MK19) использует тот же hitscan и тот же геймплейный штраф отдачи, но **другой визуальный kick ствола**. Это отмечено отдельно.

---

## Как читать

1. Сначала **§1 модель**: два канала, что влияет на пулю, что нет.
2. Затем **§2 порядок одного выстрела** — без него легко перепутать «этот выстрел» и «следующий».
3. **§3–§6** — формулы точности и отдачи с полными таблицами констант.
4. **§7–§8** — кто разрешает выстрел и как серии/паузы обнуляют отдачу.
5. **§9** — визуал (картинка и задержка курка, не конус).
6. **§10** — числовые примеры «выстрел 1 / 2 / 5 / новая серия».
7. **§11** — следствия для баланса (что крутить, чтобы изменить поведение).

Обозначения:

- `d` — дистанция до точки прицеливания, метры.
- `θ` — полуугол конуса разброса, градусы (half-angle).
- `P` — накопленный `RecoilPenalty` (безразмерный штраф, не градусы).
- `i` — номер выстрела в непрерывной авто/burst-серии, начиная с 1.
- `×` — произведение независимых множителей (все стартуют с 1, если источник отсутствует).
- `clamp(x, a, b)` — ограничение диапазона.
- `lerp(a, b, t)` — линейная интерполяция, `t` в 0…1.
- `InverseLerp(a, b, x)` — `(x − a) / (b − a)`, затем clamp 0…1.

## 1. Модель: что система вообще считает

### 1.1. Это не баллистика полёта

Пули как физического снаряда нет. Выстрел — **мгновенный луч** (hitscan) из дула до 500 м (дефолт дальности луча). «Скорость патрона» нужна только для **упреждения** движущейся цели, не для времени полёта пули в мире.

### 1.2. Два канала отдачи — их нельзя смешивать

| Канал | Что это | Входит в формулу пули? | Для чего |
|-------|---------|------------------------|----------|
| **Gameplay recoil** | Число `P` (`RecoilPenalty`), 0…30 | **Да**: ширина конуса и смещение паттерна очереди | Стабильность стрелка |
| **Visual recoil** | Импульс руки/оружия (punch) + устойчивый подъём (climb от `P`) | **Нет** в `θ`. Косвенно может **задержать** следующий выстрел, пока ствол не вернётся в допуск | Картинка |

Отдельно: реакция плеча/локтя — тоже только картинка.

Множители `VisualRecoilKickScale` и `ArmRecoilMultiplier` на оружии **не** меняют `P` и **не** меняют `θ`.

### 1.3. Куда летит луч при выбранной цели

Если есть цель:

```
направление_базы = normalize(точка_прицеливания + упреждение − origin)
направление      = поворот_паттерна(направление_базы)     // только авто/burst, i ≥ 2
направление      = случайный_конус(направление, θ)        // всегда, если θ > 0
```

**Не** «куда сейчас смотрит визуально дёрнутый ствол». Kick сдвигает точку старта луча (дуло чуть назад/вверх), но вектор при наличии цели считается **на точку прицеливания**.

Если цели нет — луч идёт вдоль `forward` дула (тогда visual kick уже влияет на направление). В бою цель обычно есть.

Упреждение:

```
время_полёта ≈ d / velocity_патрона          // velocity дефолт патрона 400 м/с
упреждение   = скорость_цели × время_полёта × TargetLeadFactor
TargetLeadFactor = 1.0 (можно 0…1.5)
```

### 1.4. Текущий выстрел не видит свою отдачу

Порядок внутри успешного выстрела фиксирован:

1. Проверки «можно ли стрелять».
2. Расход патрона + постановка таймера RPM.
3. **Hitscan с текущим `P`** (штраф от *прошлых* выстрелов).
4. Счётчик очереди `i` увеличивается.
5. Событие «выстрелили» → `P += added`, визуальный punch, сброс прицела (только одиночный).

Следствие: выстрел N использует `P` после выстрела N−1 (и восстановления за прошедшее время). Штраф выстрела N попадает в выстрел N+1.

## 2. Порядок одного кадра и одного выстрела

### 2.1. Кто что делает в кадре (логически)

Не имена скриптов, а роли:

| Когда | Роль |
|-------|------|
| Раньше курка | Дисциплина огня: начать/держать/отпустить курок по плану серии |
| Курок | Попытка выстрела: гейты → патрон → hitscan → событие выстрела |
| Сразу после курка | Набор/потеря прогресса прицеливания |
| Сразу после курка | Стекание `P` к нулю за этот кадр |
| После анимации (конец кадра) | Визуальный overlay на правую кисть, затем рука IK |

Стекание `P` в том же кадре, что и выстрел, чуть уменьшает штраф *после* hitscan. На текущую пулю это не влияет (hitscan уже прошёл). На следующую — да, если до неё есть хотя бы доля секунды.

### 2.2. Состояние «оружие в руках» (транзиент)

Пока оружие экипировано, живёт набор чисел:

| Поле | Смысл | Диапазон |
|------|--------|----------|
| `AimProgress` | Насколько наведён прицел | 0…1 |
| `P` (`RecoilPenalty`) | Накопленная отдача | 0…`P_max` |
| `consecutive` | Сколько выстрелов авто-серии уже сделано | ≥ 0 |
| `i = consecutive + 1` | Номер *следующего* выстрела серии | 1, 2, 3… |
| `NextAllowedShotTime` | Когда RPM снова разрешит выстрел | время |

`i` читается **до** инкремента: первый выстрел серии всегда `i = 1`.

## 3. Геймплейная отдача `P`

### 3.1. Добавка за один выстрел

```
режим_множитель =
    SemiAuto                         → SemiAutoRecoilMultiplier     // дефолт оружия 0.85
    FullAuto / Burst / Auto          → AutoRecoilMultiplier         // дефолт оружия 1.25

модули = произведение по всем обвесам:
    RecoilModifier × (AutomaticRecoilModifier  если авто/burst/Auto
                      SemiAutoRecoilModifier   иначе)
    каждый множитель не ниже 0.01

added = RecoilPerShot                  // дефолт оружия 1.0
      × режим_множитель
      × RecoilModifier_патрона         // дефолт 1.0
      × модули
      × skill_recoil_added             // см. §6.1, при навыке 50 = 1.0
      × traits_recoil_added            // 1 − modifier, modifier ∈ [−0.10; +0.10]
      × condition_recoil_added         // раны/боль/stamina, иначе 1
      × posture_recoil_added           // стойка×ход, иначе 1

P ← clamp(P + added, 0, P_max)
P_max = 30  (дефолт контроллера)
```

Если оружия нет — добавка 0.

### 3.2. Восстановление каждый кадр

Пока `P > 0`:

```
recovery_в_сек = RecoilRecoveryPerSecond          // дефолт оружия 3.5
               × (0.7  если курок удерживается)   // RecoveryWhileFiring
               × (1.2  если оружие не в ready)    // RecoveryWhenNotReady
               × skill_recoil_recovery            // навык 50 → 1.0
               × traits_recoil_recovery           // 1 + modifier
               × condition_recoil_recovery        // раны/боль, иначе 1
               (не ниже 0)

P ← MoveTowards(P, 0, recovery_в_сек × dt)
```

Интервал между выстрелами автоочереди:

```
Δt_выстрела = 60 / RPM
RPM = FireRateRpm                          // дефолт 600 → 0.100 с
      или SemiAutoFireRateRpm, если Semi и это поле > 0
```

Грубая оценка нетто за выстрел в очереди (курок удерживается, ready, навыки 50, без обвесов/патрона):

```
recovery_за_интервал ≈ RecoilRecoveryPerSecond × 0.7 × (60/RPM)
нетто                ≈ added − recovery_за_интервал
P растёт, пока нетто > 0, и упирается в 30.
```

Пример при дефолтах оружия (`RecoilPerShot=1`, auto×1.25, recovery 3.5, 600 RPM):

```
added                    = 1.25
recovery_за_0.1 с        = 3.5 × 0.7 × 0.1 = 0.245
нетто на выстрел         ≈ 1.005
плато                    = 30 (через ~30 выстрелов без учёта других множителей)
```

### 3.3. Жёсткий сброс `P = 0`

Когда курок отпускают (`StopFiring`) и включён сброс (в бою **включён по умолчанию**):

- `P ← 0`
- визуальный punch/climb обнуляются
- счётчик очереди `consecutive ← 0`

Это происходит в том числе:

- конец огневой серии дисциплины → пауза;
- смена цели, если система решила «надо заново наводиться»;
- перезарядка / клин / приказ остановить огонь.

**Между сериями штраф не достекает — он обнуляется.** Внутри одной очереди/серии действует §3.1–3.2.

Исключение: диагностический прогон отдачи может выключить сброс, чтобы мерить затухание. В обычной игре сброс включён.

## 4. Формула точности пули (`θ`)

### 4.1. Полное произведение

```
raw =
    BaseShotDispersion                 // оружие, дефолт 1
  × SpreadModifier_патрона             // дефолт 1
  × D_weapon(d)                        // кривая оружия 0…500 м, дефолт плоская 1
  × D_attachments(d)                   // произведение кривых модулей; оптика только в Aiming
  × (1 + P × RecoilSpreadScale)        // RecoilSpreadScale hitscan = 0.22
  × stance                             // стойка×ход или спринт
  × skill_dispersion                   // Marksmanship
  × traits_dispersion
  × condition_dispersion
  × aim_incomplete                     // неполный прицел; в авто i≥2 = 1
  × burst_curve(i)                     // кривая оружия; i=1 → 1
  × pose_spread                        // поза × кривая позы×дистанции × ЛЦУ
  × BaseSpreadToDegrees                // hitscan, дефолт 0.35

если режим FullAuto или Burst  И  i > 1:
    raw ← raw × AutoSpreadMultiplier   // дефолт 0.869565 ≈ 0.87

θ = clamp(raw, θ_min, θ_max)
θ_min = 0.04°
θ_max = 12°
```

Радиус круга рассеивания на дистанции (плоскость, перпендикулярная лучу):

```
R = d × tan(θ в радианах)
диаметр = 2R
```

Случайный конус: точка равномерно в круге радиуса `tan(θ°)`, затем направление нормализуется. Это **не** гаусс: попадание чаще ближе к оси, чем у «равномерного по углу» конуса, но край круга достижим.

`movement` как отдельный множитель в формуле **всегда 1**. Ходьба уже сидит внутри `stance`.

### 4.2. Что `P` делает с конусом

```
recoilFactor = 1 + P × 0.22
```

| `P` | recoilFactor | смысл |
|-----|--------------|--------|
| 0 | 1.00 | нет штрафа отдачи |
| 1 | 1.22 | один «типичный» semi-выстрел ещё не восстановился |
| 5 | 2.10 | короткая очередь |
| 15 | 4.30 | длинная очередь |
| 30 | 7.60 | потолок |

При нейтральных прочих множителях и `BaseSpreadToDegrees=0.35`, `BaseShotDispersion=1`:

| `P` | `θ` | `R` на 50 м | `R` на 100 м |
|-----|-----|-------------|--------------|
| 0 | 0.35° | 0.31 м | 0.61 м |
| 5 | 0.735° | 0.64 м | 1.28 м |
| 15 | 1.505° | 1.31 м | 2.63 м |
| 30 | 2.66° | 2.32 м | 4.64 м |

В бою `θ` почти всегда другая: поза, дистанция, навыки, `i`. Таблица — только вклад отдачи при «лабораторной единице».

> У контроллера отдачи есть своё поле `RecoilSpreadScale = 0.15` и debug-свойство `SpreadHalfAngle = P × 0.15`. Это **не** боевой угол. Боевой коэффициент — **0.22** в формуле выше.

### 4.3. Процедурный паттерн очереди (смещение оси, не ширина конуса)

Включается **только** если:

- эффективный режим FullAuto или Burst;
- `i ≥ 2`;
- `P > 0.0001`.

Иначе направление остаётся «точно в точку прицеливания» (потом конус).

```
basePitch° = P × 0.09 × AutoSpreadMultiplier          // 0.09 × 0.87 ≈ 0.0783 ° на единицу P

controlBlend:
    если не FullAuto → 0
    если i ≤ 5       → 0                              // FullAutoRecoilControlStartShot = 5
    иначе t = InverseLerp(5, 10, i)                   // EndShot = 10
         skill01 = InverseLerp(0, 100, RecoilControl) // навык 50 → 0.5
         controlBlend = lerp(t, t × skill01, 0.65)    // SkillInfluence = 0.65

pitch° = basePitch° × lerp(1, 0.38, controlBlend)     // вертикаль режется до 38%

yaw_ref° = basePitch° × lerp(1, 1.00, controlBlend)   // YawReferenceScale = 1
yawFraction = lerp(0.55, 1.05, controlBlend)          // от «чуть в сторону» к «горизонталь доминирует»
yawBoost    = lerp(1.00, 1.20, controlBlend)

seed зависит от id оружия (детерминированный сдвиг фазы)
main  = sin(i × 1.73 + seed)
chaos = sin(i × 0.47 + seed × 2.31) × 0.22            // ChaosFraction
yaw°  = (main + chaos) × yaw_ref° × yawFraction × yawBoost

направление = поворот вокруг мира-up на yaw°, затем вверх на pitch°
```

Смысл: первые выстрелы очереди (2…5) в основном **вверх**. К 10-му выстрелу FullAuto вертикаль слабее, боковой увод сильнее. Навык RecoilControl усиливает эту компенсацию (при 0 навыка бленд слабее).

Поверх смещённой оси **всё равно** крутится случайный конус `θ`. Паттерн = куда смотрит центр группы; конус = размер группы.

Semi-авто: паттерна нет, только конус (который растёт с `P`, если `P` не сбросили).

### 4.4. Кривая авто-разброса по номеру выстрела

На ассете оружия кривая `AutoBurstSpreadMultiplierByShot`: ось X = `i`, Y = множитель.  
`i ≤ 1` или пустая кривая → 1. Иначе `max(0.01, curve(i))`.

Дефолт в шаблоне оружия — линейная 1…1 (нейтраль). Реальные винтовки часто поднимают Y после 2–3 выстрела. Без конкретного ассета считать 1, но **канал в формуле есть**.

Дополнительно со 2-го выстрела авто/burst весь `raw` умножается на `≈0.87` (компенсация «авто точнее на 15%» как отдельная ручка, ортогональная кривой).

### 4.5. Неполный прицел (`aim_incomplete`)

Сначала множитель от прогресса (до дистанции):

| `AimProgress` | множитель |
|---------------|-----------|
| 0.00 | 3.00 |
| 0.35 (SnapShot) | 2.20 |
| 0.68 (QuickAim) | 1.45 |
| 0.85 | 1.15 |
| 1.00 | 1.00 |

Между узлами — линейная интерполяция.

Если множитель > 1, избыток масштабируется дистанцией. В коде в шкалу дистанции подставляется `d × 0.2` (то есть «эффективные метры» = 20% реальной дистанции):

```
x = d × 0.2
scale =
    x ≤ 10          → 0.60          // реальные d ≤ 50 м
    10 < x ≤ 25     → lerp 0.60…1.00
    25 < x ≤ 50     → lerp 1.00…1.25
    50 < x ≤ 100    → lerp 1.25…1.50
    x > 100         → 1.50          // реальные d > 500 м, на практике потолок дистанции кривых 500

aim_incomplete = 1 + (база − 1) × scale
```

Практично: на короткой дистанции стрельба с недобранным прицелом штрафуется слабее, на дальней — сильнее.

**В FullAuto/Burst при `i ≥ 2` этот штраф отключается** (в расчёт подставляется полный прицел). Первый выстрел очереди штраф видит.

Пороги режимов прицеливания (когда разрешён выстрел — отдельно, §7):

| Режим | нужный AimProgress | смысл |
|-------|-------------------|--------|
| SnapShot | 0.35 | вскидка |
| QuickAim | 0.68 | быстрый |
| FullAim | 1.00 | полный |

Минимальное *время* до выстрела по режиму (если полное время прицела очень короткое, пол не даёт выстрелить мгновенно): Snap 0.11 с, Quick 0.22 с. FullAim не поднимают полом, если полное время уже ≥ 0.15 с; если полное время абсурдно короткое (< 0.15 с), пол FullAim = 0.32 с.

### 4.6. Поза оружия (`pose_spread`)

База (если нет запечённого кэша — те же числа):

| Поза | можно стрелять? | база spread | порог AimProgress для выстрела |
|------|-----------------|-------------|--------------------------------|
| HipFire / HipFireWalk / HipFireCrouchWalk | да | 2.50 | 0.35 |
| PointAim | да | 1.50 | 0.65 |
| Aiming | да | 1.00 | 1.00 (или выше по дисциплине) |
| PreAim | **нет** | 1.75 | — |
| LowReady / HighReady / NotReady / Patrol | нет | — | — |

Оптика в `D_attachments` **не участвует** в HipFire, PointAim, PreAim. Участвует только в Aiming.

Поверх базы — кривая поза×дистанция (линейная интерполяция между узлами). Множитель **к разбросу** (больше = хуже):

**HipFire**

| м | × |
|---|---|
| 0–3 | 1.00 |
| 5 | 1.10 |
| 10 | 1.50 |
| 15 | 2.20 |
| 25 | 3.50 |
| 50 | 6.00 |
| 100 | 10.00 |
| 500 | 16.00 |

**PointAim**

| м | × |
|---|---|
| 0–5 | 1.00 |
| 10 | 1.05 |
| 25 | 1.20 |
| 50 | 1.45 |
| 100 | 1.90 |
| 200 | 3.00 |
| 300 | 4.20 |
| 500 | 7.00 |

**Aiming** (и PreAim для этой кривой)

| м | × |
|---|---|
| 0–25 | 1.00 |
| 50 | 1.02 |
| 100 | 1.05 |
| 200 | 1.08 |
| 300 | 1.10 |
| 500 | 1.15 |

ЛЦУ (лазер) **только PointAim**:

```
laser(d) = lerp(1, peak, effect01(d))
peak < 1 → точнее
effect01 берётся с кривой модуля (1 близко, 0 далеко)
в Aiming лазер не сужает конус; может чуть ускорить набор прицела
```

Итого:

```
pose_spread = база_позы × кривая_позы(d) × (laser(d) если PointAim иначе 1)
```

### 4.7. Стойка и движение (`stance`)

Если есть таблица стойки×хода (на юните она есть по умолчанию), берётся **один** множитель (не произведение «стойка × отдельно ход»):

| Состояние | spread | время прицела | добавка отдачи |
|-----------|--------|---------------|----------------|
| Стоя на месте | 1.00 | 1.00 | 1.00 |
| Сидя/лёжа на месте | 0.92 | 1.10 | 0.95 |
| Шаг стоя | 1.25 | 1.55 | 1.25 |
| Шаг сидя/лёжа | 1.12 | 1.30 | 1.10 |
| Тащит раненого | 1.04 | 1.10 | 1.05 |
| Спринт | 2.00 | — | огонь обычно уже запрещён ready |

Если этой таблицы нет — fallback hitscan: стоя 1.00 / присед 0.90 / лёжа 0.75, и отдельно ход ×1.35.

Спринт в формуле точности ×2, но на практике выстрел из спринта чаще отсекается раньше (оружие не ready).

### 4.8. Дробовик (если патрон с паттерном и >1 снаряд)

Вместо чистого случайного конуса: 1 центр + внутреннее кольцо + внешнее кольцо, каждое с джиттером угла/радиуса.

```
θ_дроби = θ × ShotgunSpreadDistanceScale(d)
дефолт кривой: 0–15 м → 0.85; 35 м → 1.00; 70 м → 1.25
```

Лимит попаданий в одну цель за выстрел: 6 (7 если среди попаданий есть голова/шея). Лишние дробины в эту цель урон не наносят.

Урон дробины по дистанции попадания (дефолт кривой): полный до 12 м, 0.75 на 20 м, 0.45 на 35 м, 0.20 на 50 м, 0 на 70 м. Если кривой нет — общий falloff оружия (§4.9).

### 4.9. Урон по дистанции (не разброс, но тот же выстрел)

```
effective = EffectiveRange оружия × произведение EffectiveRangeModifier модулей
если у патрона EffectiveRange > 0.1 — берётся min(effective, патрон)

если d ≤ effective → урон × 1
если d ≥ effective × 2 → урон × 0     // FalloffZeroRangeMultiplier = 2
иначе линейно от 1 до 0
```

## 5. Время прицеливания (влияет на следующий выстрел косвенно)

Прогресс растёт к 1, если можно копить (ready/поза, есть цель, не reload, не смена стойки):

```
AimProgress ← MoveTowards(AimProgress, 1, dt / T)
```

Если копить нельзя — теряется быстрее:

```
AimProgress ← MoveTowards(AimProgress, 0, dt / T × 1.65)
```

`T` — полное время до AimProgress=1.

Предпочтительный расчёт (есть запечённый кэш позы):

```
T = AimTimeSeconds_оружия                  // дефолт 0.28 с
  × D_weapon_aim(d)                        // кривая оружия
  × запечённый_множитель_позы              // навыки + плоские модули + фактор позы
  × кривая_позы_aim(d)
  × posture_aim                            // стойка×ход
  × лазер_aim                              // PointAim: product(d); Aiming: маленький acquisition
  не ниже 0.01 с
```

Факторы позы в fallback без кэша: HipFire ×0.55, PointAim ×0.85, PreAim ×0.70, Aiming ×1.

Кривые **времени** прицела поза×дистанция (меньше 1 = быстрее; здесь все ≥ 1):

**HipFire:** 0–15 м ×1; 50 ×1.05; 100 ×1.10; 500 ×1.20  
**PointAim:** 0–25 ×1; 100 ×1.08; 300 ×1.15; 500 ×1.25  
**Aiming:** 0–25 ×1; 100 ×1.05; 300 ×1.10; 500 ×1.15  
**PreAim:** 0 ×1; 50 ×1.02; 200 ×1.08; 500 ×1.12

После **одиночного** выстрела `AimProgress ← 0`. Следующий semi ждёт порог заново.

После выстрела **авто/burst** этот сброс **не** делается. После *волны* burst (кончились патроны волны) прогресс ставится в 0 на паузу между волнами.

Смена цели: не полный сброс, а `AimProgress × carryover`. Carryover = 0.8 при угле 0° между старой и новой точкой, линейно до 0 при угле ≥ 25°. В FullAuto при смене цели прогресс всё же в 0.

## 6. Юнит: навыки, характер, состояние

### 6.1. Навыки (0…100, 50 = нейтраль)

```
множитель = lerp(худший, лучший, skill/100)
не ниже 0.01
```

| Навык | Куда | 0 | 50 | 100 |
|-------|------|---|----|-----|
| Marksmanship | `θ` | 1.25 | 1.00 | 0.75 |
| WeaponHandling | `T` | 1.25 | 1.00 | 0.75 |
| RecoilControl | `added` | 1.20 | 1.00 | 0.80 |
| RecoilControl | `recovery` | 0.80 | 1.00 | 1.20 |
| RecoilControl | бленд паттерна FullAuto | `skill01 = skill/100` | | |

### 6.2. Индивидуальные черты (±10%, случайный бросок на старт сессии)

```
dispersion     = max(0.01, 1 − MarksmanshipModifier)
aim_time       = max(0.01, 1 − WeaponHandlingModifier)
recoil_added   = max(0.01, 1 − RecoilControlModifier)
recoil_recovery= max(0.01, 1 + RecoilControlModifier)
```

Плюс личность дисциплины: `FireAggression` (больше → длиннее очереди, короче паузы), `FireCadence` (больше → длиннее паузы). Диапазон каждого ±0.10.

### 6.3. Состояние (флаги, множители перемножаются)

| Флаг | разброс | время прицела | added recoil | recovery recoil |
|------|---------|---------------|--------------|-----------------|
| Раны рук | ×1.35 | ×1.25 | ×1.25 | ×0.85 |
| Раны ног | — | ×1.20 только в движении | — | — |
| Сильная боль | ×1.20 | ×1.15 | ×1.10 | ×0.90 |
| Подавление | ×1.15 | ×1.20 | — | — |
| Исчерпана ready-stamina | ×1.20 | — | ×1.50 | — |

Нет флагов → все 1.

## 7. Когда выстрел вообще разрешён

Все пункты должны пройти. Иначе выстрела нет, `P` не растёт.

1. Юнит в сознании.
2. Поза из разрешённых для спуска: HipFire / PointAim / Aiming (не PreAim). Турель — исключение.
3. Оружие в ready (если проверка включена — по умолчанию да).
4. Не занят: смена стойки, перезарядка, бросок, РПГ, стабилизация, proximity-relax.
5. Есть намерение огня по цели (видимая цель / решение «Fire»).
6. **AimProgress ≥ порога**  
   - Semi: каждый выстрел.  
   - FullAuto/Burst: только пока `i = 1`.  
   Порог = max(порог позы из §4.6, порог плана дисциплины).
7. **Угол ствол→цель ≤ допуска** (если проверка включена — да). Допуск:

   | Поза | стоя на месте | стоя в ходе | сидя/лёжа на месте | сидя/лёжа в ходе |
   |------|---------------|-------------|--------------------|------------------|
   | Aiming | 3° | 8° | 9° | 9° |
   | PointAim | 5° | 10° | 7° | 11° |
   | HipFire | 12° | 16° | 14° | 18° |

   Visual punch крутит кисть → ствол. Пока угол больше допуска, автоочередь получает отказ «ствол не наведён», даже если RPM уже тикнул. Это **темп**, не `θ`. Передёргивание затвора (пустой патронник при полном магазине) этот gate пропускает.

8. Линия огня: толстый луч радиусом 0.35 м. Союзник или нейтрал с зоной тела на пути — блок. Повтор проверки не чаще чем раз в 0.15 с.
9. RPM: текущее время ≥ `NextAllowedShotTime`.
10. Есть патрон в патроннике (иначе bolt-cycle / пустой магазин). Нет клина.

Удержание курка в авто: каждый кадр новая попытка, режет RPM. Burst: волна `BurstRounds` (дефолт 3), пауза `BurstPauseSeconds` (дефолт 0.12 с), на паузе AimProgress = 0. Дисциплина может подменить длину волны и паузу.

## 8. Огневая дисциплина: серии и зачем это бьёт по отдаче

Вместо бесконечной очереди юнит стреляет **сериями** с паузами.

Цикл: простой → набор прицела → огонь, пока не сделано N выстрелов → отпустить курок → пауза → новый план.

Отпускание курка **обнуляет `P`**. Первая пуля новой серии не несёт штраф предыдущей очереди. Внутри серии `P` копится как в §3.

Длина серии, пауза и порог прицела бросаются случайно в диапазоне «полосы». Полоса зависит от дисциплины, класса оружия и дистанции.

Дисциплины: экономный / точный / подавляющий / авто (авто выбирает дисциплину по дистанции, классу, меткости и агрессии).

Ниже — **базовые полосы до** правки характером. Формат: выстрелов min–max, пауза сек min–max, AimProgress min–max, предпочитаемый режим.

Дистанции полос: ≤30 / ≤80 / ≤140 / дальше.

### 8.1. Винтовка / прочее (не пулемёт, не HMG/AGL)

**Подавляющий**

| d | выстрелы | пауза с | прицел | режим |
|---|----------|---------|--------|-------|
| ≤30 | 3–7 | 0.18–0.45 | 0.28–0.52 | FullAuto |
| ≤80 | 3–5 | 0.28–0.65 | 0.40–0.68 | FullAuto |
| ≤140 | 2–4 | 0.45–0.95 | 0.55–0.82 | FullAuto |
| >140 | 1–2 | 0.70–1.40 | 0.75–1.00 | Semi |

**Точный** (default-ветка)

| d | выстрелы | пауза с | прицел | режим |
|---|----------|---------|--------|-------|
| ≤30 | 2–4 | 0.28–0.60 | 0.38–0.65 | Burst |
| ≤80 | 2–3 | 0.40–0.85 | 0.50–0.80 | Burst |
| ≤140 | 1–2 | 0.55–1.15 | 0.70–0.95 | Semi |
| >140 | 1–2 | 0.80–1.50 | 0.85–1.00 | Semi |

**Экономный**

| d | выстрелы | пауза с | прицел | режим |
|---|----------|---------|--------|-------|
| ≤30 | 1–2 | 0.45–0.90 | 0.70–0.95 | Semi |
| ≤80 | 1–2 | 0.60–1.20 | 0.85–1.00 | Semi |
| ≤140 | 1–1 | 0.85–1.60 | 0.95–1.00 | Semi |
| >140 | 1–1 | 1.00–2.00 | 1.00 | Semi |

### 8.2. Ручной пулемёт (LMG) — те же дистанции, длиннее очереди

**Подавляющий:** 8–16 / 6–14 / 5–12 / 3–8 выстрелов; паузы короче (0.10–0.28 … 0.35–0.85); режим FullAuto (на >140 тоже FullAuto).  
**Точный:** 5–10 / 4–8 / 3–6 / 2–4; на ближних FullAuto, на дальних Burst.  
**Экономный:** 2–4 / 2–3 / 1–2 / 1–1; ближние Burst, дальние Semi.

### 8.3. Крупнокалибер / АГС (HMG, AGL)

Всегда предпочитают FullAuto. Подавляющий на ≤30 м: 25–40 выстрелов, пауза 0.06–0.14 с, прицел 0.12–0.25. Дальше очереди короче, паузы длиннее.

### 8.4. После броска полосы

- Серия: целое случайное в [min, max].
- Пауза: случайное в [min, max], затем × джиттер 0.85…1.20 в момент входа в паузу.
- AimProgress плана: случайное в [min, max], затем не ниже `0.85 × базовый_порог_режима_прицела`.
- Если выбран Semi — длина серии clamp к полосе, может быть 1.
- Если Burst у не-пулемёта — длина clamp к `BurstRounds` оружия ±1 (не короче 2).
- Если селектор оружия не Auto — effective режим = выбранный игроком/юнитом (с fallback если режим не поддерживается).

Правка характером (сжато): агрессия удлиняет подавляющие очереди и коротит паузы; у точного высокий навык может укоротить max выстрелов на 1; cadence удлиняет паузы. Пауза после правки не ниже 0.08 с.

Авто-выбор дисциплины (если режим дисциплины Auto), винтовка:

- ≤25 м: подавляющий, если агрессия > 0.04 или меткость < 42; иначе точный.
- ≤70 м: подавляющий если агрессия > 0.06; экономный если меткость ≥ 62 и агрессия < 0; иначе точный.
- ≤140 м: экономный если меткость ≥ 58; иначе точный (с оговоркой по агрессии).
- дальше: экономный.

LMG по умолчанию давит огнём почти до 220 м. HMG/AGL всегда подавляющий. Пистолет/дробовик: близко точный или подавляющий, дальше экономный.

## 9. Визуальная отдача (картинка)

Не входит в `θ`. Нужна, чтобы понимать gate ствола и «почему очередь визуально прёт вверх».

На каждый выстрел:

```
impulse_добавка = added_геймплей × VisualRecoilKickScale     // kickScale с ассета, часто ~1.0–1.2
impulse ← min(impulse + добавка, 6)                          // кап силы
yaw_punch накапливается с шумом Perlin и bias вправо, кап ±6°
```

Затухание punch каждый кадр:

```
tau = 0.08 с
если курок удерживается: tau × 1.75 ≈ 0.14 с
impulse *= exp(−dt / tau)
```

Разложение punch (дефолты):

```
punchPitch° = impulse × 2.5
back м      = impulse × 0.035 × 1.0     // назад вдоль ствола — главное
up м        = impulse × 0.008 × 0.75    // вверх — малое
на кисть: pitch × 0.80, yaw × 0.85
```

Устойчивый подъём (climb) — **только вращение**, без сдвига, чтобы очередь не «вытягивала» руки:

```
climbPitch° = PitchCurve(P) × 1.0 × VisualRecoilKickScale

кривая по умолчанию:
    P=0  → 0.0°
    P=15 → 0.6°
    P=30 → 1.7°
    P=60 → 4.5°   // P капится 30, верхние ключи почти не достигаются
```

Итог на кисти: `climb + punch` по тангажу, punch по рысканью, сдвиг назад/вверх в пространстве ствола.

Камера далеко → визуал выключается (экономия). Рэгдолл / турель / передёргивание затвора — тоже.

Турель: отдельный kick ствола/люльки (например M2: ствол назад ~28 мм, pitch до 0.9° за выстрел, возврат градусами в секунду). Это не `P`.

## 10. Числовые сценарии (лаборатория)

Общие допущения примеров, если не сказано иное:

- поза Aiming, стоя на месте, навыки 50, черты 0, без ран/модулей/патронных модификаторов;
- `BaseShotDispersion=1`, `BaseSpreadToDegrees=0.35`, кривые дистанции = 1;
- `RecoilPerShot=1`, semi×0.85, auto×1.25, recovery 3.5/с, RPM 600;
- `d = 50 м`;
- AimProgress на выстреле = 1, если не оговорено;
- курок удерживается между выстрелами очереди (recovery ×0.7);
- восстановлением за долю кадра выстрела пренебрегаем; между выстрелами авто — полный интервал 0.10 с.

### 10.1. Два одиночных (Semi), без паузы дисциплины

Выстрел 1: `P=0`, `i` не важен, паттерна нет.

```
θ = 0.35°
R(50 м) ≈ 0.31 м
после выстрела: P = 0.85, AimProgress = 0
```

Пока снова набирается прицел (`T ≈ 0.28 с` × aim-кривые ≈ 0.28…0.3 с до 1.0):

```
P стекает при удерживаемом курке: 3.5 × 0.7 = 2.45 /с
за 0.28 с: P ≈ max(0, 0.85 − 2.45×0.28) ≈ 0.16
```

Выстрел 2 (успел набрать прицел):

```
recoilFactor = 1 + 0.16×0.22 ≈ 1.035
θ ≈ 0.36°   // почти как первый
```

Если стрелять не дождавшись AimProgress=1, а на 0.68:

```
aim_incomplete на 50 м: база 1.45, x=d×0.2=10 → scale=0.60
aim = 1 + 0.45×0.60 = 1.27
θ ≈ 0.35 × 1.035 × 1.27 ≈ 0.46°
```

Если после первого выстрела **отпустили курок** (конец серии дисциплины): `P=0` мгновенно. Второй выстрел новой серии как первый по отдаче, но AimProgress надо набрать снова.

### 10.2. Очередь FullAuto, выстрелы 1 / 2 / 5 / 10

Между выстрелами `Δt=0.10 с`, `added=1.25`, recovery `0.245`.

| i | P в момент выстрела (до добавки) | recoilFactor | burst×auto | паттерн |
|---|----------------------------------|--------------|------------|---------|
| 1 | 0 | 1.00 | кривая 1, без ×0.87 | нет |
| 2 | 1.005 | 1.221 | ×0.87 и кривая(2) | да, вверх от P |
| 5 | ≈ 4.02 | 1.884 | ×0.87 | да; controlBlend ещё 0 |
| 10 | ≈ 9.05 | 2.991 | ×0.87 | да; controlBlend > 0, вертикаль режется |

Грубая рекурсия: `P_{n+1} = min(30, P_n + 1.25 − 0.245)` после выстрела n, на выстреле n+1 используется уже это значение (hitscan до добавки текущего).

Выстрел 1: `θ = 0.35°`, ось точно в цель.  
Выстрел 2: `θ ≈ 0.35 × 1.221 × 0.87 ≈ 0.37°` плюс смещение оси вверх ≈ `1.005 × 0.0783 ≈ 0.08°` (мало).  
Выстрел 5: `θ ≈ 0.35 × 1.884 × 0.87 ≈ 0.57°`, pitch оси ≈ `4.02 × 0.0783 ≈ 0.31°` → вертикальное смещение центра группы на 50 м ≈ `50 × tan(0.31°) ≈ 0.27 м`.  
Выстрел 10: конус шире (~0.91° при нейтральной кривой burst), центр группы выше и гуляет по yaw; компенсация RecoilControl начинает уводить в сторону вместо чистого «ухода в небо».

Если кривая `AutoBurstSpreadMultiplierByShot` на ассете в точке 10 равна например 1.4, выстрел 10 дополнительно ×1.4.

На 50 м при `θ=0.57°`: `R ≈ 0.50 м` (диаметр ~1.0 м) — уже заметно шире «человеческой» ширины 0.60 м.

### 10.3. HipFire vs Aiming на 50 м, P=0

Aiming: `pose_spread = 1.00 × 1.02 = 1.02` → `θ ≈ 0.357°`.  
HipFire: `pose_spread = 2.50 × 6.00 = 15` → `θ ≈ 5.25°`, clamp до 12 не срабатывает.  
`R_hip(50) ≈ 4.6 м` против `R_aim ≈ 0.31 м`.

Отдача на HipFire всё ещё множится сверху: при `P=5` HipFire `θ ≈ 5.25 × 2.10 ≈ 11.0°`.

### 10.4. Автовыбор «приемлемого» режима (если нет дисциплины и селектор Auto)

Считается ожидаемый диаметр рассеивания на «типичном» выстреле (5-й в авто, 3-й в burst, 1-й в semi) и сравнивается с

```
диаметр_ок = 0.60 / √0.60 ≈ 0.775 м
```

(модель: ширина человека 0.60 м, доля попаданий 60%). Первый кандидат режим_огня × режим_прицела, у которого диаметр ≤ 0.775 м, побеждает: перебор FullAuto→Burst→Semi и Snap→Quick→Full. Если никто не прошёл — последний fallback (обычно Semi+FullAim).

В бою с включённой дисциплиной effective режим берётся из **плана серии**, не из этого селектора.

## 11. Следствия для анализа и баланса

### 11.1. Рычаги, которые реально меняют точность следующей пули

| Рычаг | Что получите |
|-------|----------------|
| `RecoilPerShot`, auto/semi множители, патрон, ДТК/приклад (`RecoilModifier`) | скорость роста `P` → и конус, и паттерн |
| `RecoilRecoveryPerSecond` | насколько очередь «садится» между выстрелами |
| RPM | меньше интервал → меньше recovery за выстрел → выше плато `P` |
| `RecoilSpreadScale` 0.22 | чувствительность конуса к уже накопленному `P` |
| `P_max` 30 | потолок хаоса длинной очереди |
| кривая `AutoBurstSpreadMultiplierByShot` | штраф именно поздних выстрелов очереди, отдельно от `P` |
| `AutoSpreadMultiplier` ~0.87 | глобально чуть сужает конус со 2-го выстрела авто |
| 0.09° на единицу `P` + таблица FullAuto control | куда едет *центр* группы, не размер группы |
| поза и её дистанционные кривые | часто сильнее отдачи (HipFire на 50 м) |
| AimProgress / дисциплина порога | semi и 1-й выстрел очереди |
| `StopFiring` сбрасывает `P` | паузы дисциплины обнуляют отдачу; длина серии важнее recovery на паузе |
| RecoilControl навык | и рост `P`, и recovery, и боковой увод вместо вертикали |
| VisualRecoilKickScale, ShotPitch, BackScale | картинка и задержки из-за допуска ствола, **не** `θ` |

### 11.2. Типичные ловушки при чтении логов / игры

1. «Ствол визуально ушёл — пуля должна уйти туда же» — нет, при цели луч на точку прицеливания + паттерн + конус.
2. «После очереди пауза 0.5 с, отдача должна частично остаться» — нет, пауза дисциплины отпускает курок и **обнуляет** `P`.
3. «Первый выстрел очереди уже с авто-штрафом» — нет: `i=1` без паттерна, без burst-кривой, без ×0.87, с полным влиянием AimProgress.
4. Debug `SpreadHalfAngle` контроллера отдачи (`P×0.15`) ≠ боевой `θ`.
5. `VisualRecoilKickScale` не лечит разброс.
6. Два `RecoilSpreadScale` в проекте расходятся (0.15 vs 0.22) — для анализа пуль использовать **0.22**.

### 11.3. Что сознательно не входит в `θ`

Анимация, IK, наклон корпуса, визуальный punch/climb, реакция плеча, звук, гильзы, трассер, износ/грязь/клин (клин **запрещает** выстрел, но не множит конус), броня цели, упреждение (меняет точку, не ширину), falloff урона.

Износ и грязь могут прервать очередь клином — тогда серия кончается, курок отпускают, `P` сбрасывается.

## 12. Сводка формул на одной странице

```
i = consecutive + 1                          // читается до инкремента
Δt = 60 / RPM

added = RecoilPerShot × (semi 0.85 | auto 1.25)
      × патрон × модули × навыки × черты × состояние × стойка

после успешного выстрела (после hitscan):
    P = clamp(P + added, 0, 30)
    если Semi: AimProgress = 0
    если авто/burst: consecutive += 1

каждый кадр:
    P → 0 со скоростью RecoilRecoveryPerSecond
        × 0.7 если курок зажат
        × 1.2 если не ready
        × recovery-навыки/черты/состояние

StopFiring (дефолт): P = 0, visual = 0, consecutive = 0

recoilFactor = 1 + P × 0.22

θ = clamp(
      BaseDispersion × патрон_spread × D_weapon(d) × D_attach(d)
    × recoilFactor × stance × skill × traits × condition
    × aim_incomplete(i==1) × burst_curve(i) × pose_spread(d)
    × 0.35
    × (0.87 если авто/burst и i>1),
      0.04°, 12°)

направление = на_цель + lead
            затем если авто/burst и i≥2: паттерн(P, i, RecoilControl)
            затем случайный конус θ

R = d × tan(θ°)
```

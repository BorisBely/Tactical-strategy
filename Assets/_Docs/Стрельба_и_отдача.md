# Стрельба и отдача (самодостаточный разбор)

Документ описывает **пехотную hitscan-стрельбу** юнита: как выбирается направление пули, как копится отдача и как она меняет **следующий** выстрел. Его можно анализировать **без проекта и без кода**.

Снимок логики: **2026-08-21**. Модель gameplay recoil — накопленный угловой `RecoilOffset` (градусы). Старый безразмерный `RecoilPenalty` (`P`) и раздувание конуса от `P` **больше не существуют**.

Excel с параметрами каждого ствола: `Tools/CombatBalanceParameters.xlsx` (генератор `Tools/export_combat_balance_excel.py`). Лист **Параметры** — живые поля ассетов, включая новые градусы. Лист **Отдача** — ещё старая модель P, не калибровать по нему.

Числа ниже — **дефолты из кода** и стартовые значения ассетов после миграции. Конкретное оружие / патрон / префаб юнита в инспекторе могут отличаться; формулы при этом те же.

Турель (M2 / MK19) использует тот же hitscan и тот же `RecoilOffset`, но **другой визуальный kick ствола**.

## Как читать

1. Сначала **§1 модель**: два канала, что влияет на пулю, что нет.
2. Затем **§2 порядок одного выстрела** — без него легко перепутать «этот выстрел» и «следующий».
3. **§3–§5** — формулы точности (конус) и отдачи (offset).
4. **§6–§7** — кто разрешает выстрел и что происходит на паузе очереди.
5. **§8** — визуал (картинка и задержка курка, не направление пули).
6. **§9** — числовые примеры «выстрел 1 / 2 / 5».
7. **§10** — что крутить, чтобы изменить поведение.
8. **§11** — что больше не существует.
9. **§12** — полный каталог множителей точности и отдачи (все источники).
10. **§13** — позы, стойка, движение: что происходит с пулей прямо сейчас.
11. **§14** — системы на переработку. По этому разделу можно составить план работ, не открывая репозиторий.

Обозначения:

- `d` — дистанция до точки прицеливания, метры.
- `θ` — полуугол **intrinsic** конуса разброса, градусы (half-angle). Не зависит от отдачи.
- `Offset` — `Vector2` в градусах: `x` = yaw (вправо +, влево −), `y` = pitch вверх (+).
- `Kick` — дельта offset за один успешный выстрел, градусы.
- `i` — номер уже сделанного выстрела с этим оружием в руках (`RecoilShotIndex` после выстрела). Для формулы kick текущего выстрела берётся `i = RecoilShotIndex + 1`.
- `m` — общий множитель импульса (режим огня × патрон × модули × навык × состояние × поза).
- `×` — произведение независимых множителей (все стартуют с 1, если источник отсутствует).
- `clamp(x, a, b)` — ограничение диапазона.
- `lerp(a, b, t)` — линейная интерполяция, `t` в 0…1.
- `MoveTowards(a, b, maxDelta)` — шаг от `a` к `b` не больше `maxDelta`.

## 1. Модель: что система вообще считает

### 1.1. Это не баллистика полёта

Пули как физического снаряда нет. Выстрел — **мгновенный луч** (hitscan) из дула до 500 м (дефолт дальности луча). «Скорость патрона» нужна только для **упреждения** движущейся цели, не для времени полёта пули в мире.

### 1.2. Два канала — их нельзя смешивать

| Канал | Что это | Входит в формулу пули? | Для чего |
|-------|---------|------------------------|----------|
| **Accuracy** | Маленький случайный конус вокруг *текущей* точки прицеливания | **Да**: `θ` | Intrinsic неточность оружия, поза, навыки, неполный прицел |
| **Gameplay recoil** | Накопленный `RecoilOffset` (градусы yaw/pitch) | **Да**: поворот центра очереди. **Нет** в ширине `θ` | Соседние пули связаны; очередь уходит вверх и в сторону |
| **Visual recoil** | Импульс руки/оружия (punch) + устойчивый подъём (climb от `Offset.y`) | **Нет** в направлении при выбранной цели. Косвенно может **задержать** следующий выстрел, пока ствол не вернётся в допуск | Картинка |

Множители `VisualRecoilKickScale` и `ArmRecoilMultiplier` на оружии **не** меняют `Offset` и **не** меняют `θ`.

### 1.3. Куда летит луч при выбранной цели

Если есть цель:

```
направление_базы = normalize(точка_прицеливания + упреждение − origin)
направление      = поворот(направление_базы, Offset)   // yaw вокруг up, pitch вверх
направление      = случайный_конус(направление, θ)     // всегда, если θ > 0
```

**Не** «куда сейчас смотрит визуально дёрнутый ствол». Kick сдвигает точку старта луча (дуло чуть назад/вверх), но вектор при наличии цели считается **на точку прицеливания + Offset**.

Если цели нет — луч идёт вдоль `forward` дула (тогда visual kick уже влияет на направление). В бою цель обычно есть.

Упреждение:

```
время_полёта ≈ d / velocity_патрона          // velocity дефолт патрона 400 м/с
упреждение   = скорость_цели × время_полёта × TargetLeadFactor
TargetLeadFactor = 1.0 (можно 0…1.5)
```

Поворот offset (как в коде):

```
up    = world up, если ствол не смотрит почти вертикально; иначе world forward
right = cross(up, forward)
rotation = AngleAxis(Offset.x, up) * AngleAxis(−Offset.y, right)
направление = rotation * forward
```

Смещение точки попадания на дистанции `d` от одного только offset (без конуса):

```
смещение_м ≈ d × tan(|Offset| × π/180)
```

На 100 м: `1° ≈ 1.75 м`.

### 1.4. Текущий выстрел не видит свой kick

Порядок внутри успешного выстрела фиксирован:

1. Проверки «можно ли стрелять».
2. Расход патрона + постановка таймера RPM.
3. **Hitscan с текущим `Offset`** (kick от *прошлых* выстрелов, уже уменьшенный recovery).
4. Счётчик burst-очереди для гейта прицеливания увеличивается (это не recoil).
5. Событие `ShotFired`.
6. **Gameplay recoil: `Offset += Kick`** — только для *следующего* выстрела.
7. Visual punch от величины этого kick.

Пуля №1: `Offset = (0, 0)` + tiny cone. Пуля №2 уже сидит на kick первой.

Компенсации стрелка («тянет прицел обратно») **нет**. Навык RecoilControl только уменьшает kick и ускоряет recovery.

## 2. Порядок одного выстрела (тайминг)

Контроллер огня (`executionOrder` 55) вызывает hitscan (`57`) **до** `ShotFired`. Recoil-контроллер (`58`) подписан на `ShotFired` и добавляет kick **после** луча.

```
кадр N, успешный выстрел
  TryConsumeShot                    // патрон израсходован
  Hitscan.ProcessSuccessfulShot     // луч: aim + Offset_текущий + cone(θ)
  RegisterBurstShotFired            // i_burst += 1  (гейт прицела, не recoil)
  ShotFired
    RecoilController                // Offset += Kick; RecoilShotIndex += 1
    UnitWeaponRecoil                // visual punch
    прочие подписчики
каждый кадр (в т.ч. между выстрелами и на паузе дисциплины)
  Offset = MoveTowards(Offset, 0, RecoilRecovery × множители × dt)
```

`StopFiring` (в том числе пауза fire discipline) **не обнуляет** gameplay `Offset` и `RecoilShotIndex`. Пауза = recovery. Сброс только при снятии оружия / `Clear()`. Visual punch при `StopFiring` по-прежнему может сбрасываться (`ResetVisualKick`); climb на следующем кадре снова читает `Offset.y`.

## 3. Accuracy — маленький конус `θ`

### 3.1. Формула

```
raw = BaseShotDispersion
    × SpreadModifier_патрона
    × DistanceDispersion_оружия(d)
    × ∏ DistanceDispersion_модуля(d)     // оптика исключается в HipFire / PointAim / PreAim
    × Stance/PostureSpread
    × SkillSpread × TraitsSpread × ConditionSpread
    × IncompleteAimSpread(AimProgress, d)
    × PoseSpread                         // HipFire 2.5, PointAim 1.5, Aiming 1, × кривые дистанции
    × BaseSpreadToDegrees                // дефолт 0.35

θ = clamp(raw, MinHalfAngle, MaxHalfAngle)
    MinHalfAngle = 0.04°
    MaxHalfAngle = 12°
```

В формуле **нет**:

- `RecoilOffset` / бывшего `P`
- `1 + P × RecoilSpreadScale`
- `AutoSpreadMultiplier` (старый 0.87 на авто)
- `AutoBurstSpreadMultiplierByShot` (кривая по номеру очереди)

Это были костыли огромного конуса. Кривая `AutoBurstSpreadMultiplierByShot` на ассете ещё лежит, но hitscan её не читает.

Случайный конус: точка внутри круга радиуса `tan(θ)` в плоскости, перпендикулярной направлению (уже повёрнутому на Offset).

Диаметр пятна на дистанции (только конус, без offset):

```
диаметр_м = 2 × d × tan(θ × π/180)
```

### 3.2. Неполный прицел

Для 2-го и далее выстрела Burst/FullAuto `AimProgress` для разброса форсируется в 1. Первый выстрел серии может быть шире, если прицел не доведён.

### 3.3. Типичный порядок `θ` (M4, Aiming, полный прицел, 100 м)

`BaseShotDispersion ≈ 0.55`, `BaseSpreadToDegrees = 0.35` → raw ≈ `0.19°` до дистанции/позы. Это **не** бывшие 2–5° от накопленного `P`. Очередь больше не «размазывается облаком»; она **смещается целиком**.

## 4. Gameplay recoil — `RecoilOffset`

### 4.1. Состояние (пока оружие в руках)

```
Offset        Vector2   градусы, x = yaw, y = pitch вверх
PatternValue  float     сглаженный горизонтальный сигнал, примерно −1…1
ShotIndex     int       сколько успешных выстрелов сделано с этим экземпляром в руках
```

Страховочный кап: `|Offset| ≤ 12°` (поле контроллера `MaxRecoilOffsetDegrees`).

### 4.2. Kick (только успешный выстрел)

`i = ShotIndex + 1`

```
verticalVariation = lerp(0.85, 1.15, Hash01(seed, i, 0))

rawPattern = sin(seed + i × 0.73) × 0.65
           + sin(seed × 1.7 + i × 1.31) × 0.35

pattern    = lerp(PatternValue, rawPattern, 0.35)

m = fireModeMult
  × ammo.RecoilModifier
  × ∏ attachment.GetRecoilModifier(fireMode)
  × RecoilControl_added          // навык, типично 0.8…1.2
  × traits × condition × posture

deltaY = VerticalRecoil × verticalVariation × m
deltaX = HorizontalRecoil × pattern × m

deltaY = clamp(deltaY, 0, VerticalRecoil × 1.20 × m)
deltaX = clamp(deltaX, −HorizontalRecoil × 1.25 × m, +HorizontalRecoil × 1.25 × m)

Offset += (deltaX, deltaY)
если |Offset| > 12°: Offset *= 12 / |Offset|

PatternValue = pattern
ShotIndex   += 1
```

`fireModeMult`:

| Режим | Поле оружия | Типичное значение |
|-------|-------------|-------------------|
| SemiAuto | `SemiAutoRecoilMultiplier` | 0.74…0.90 |
| FullAuto / Burst / Auto | `AutoRecoilMultiplier` | 1.0…1.45 |

`seed = RecoilPatternSeed_оружия + (instanceId & 1023) × 0.017`

Два одинаковых автомата в руках разных юнитов рисуют родственников, но не один и тот же синус. Сто очередей одного ствола остаются похожими (`ShotIndex` и seed экземпляра стабильны, пока оружие не сняли).

`sin` считается **только в момент выстрела**, не каждый кадр.

Вертикальный kick **не бывает отрицательным**. Вниз очередь возвращается только recovery.

### 4.3. Recovery (каждый кадр)

```
rate = RecoilRecoveryPerSecond          // °/с на ассете оружия
     × (IsFiring ? 0.7 : 1.0)
     × (не ready ? 1.2 : 1.0)
     × skill_recovery × traits_recovery × condition_recovery

Offset = MoveTowards(Offset, (0,0), rate × dt)
```

Единица — **градусы в секунду**, не старые единицы `P`. Старые 3.5–5 на ассетах **нельзя** читать как °/с: при kick 0.12° и интервале 0.1 с recovery 3.5°/с съест 0.35° за интервал, и очередь не поднимется.

Пока курок зажат, recovery медленнее (×0.7), чтобы нетто kick на 600 RPM оставался положительным.

### 4.4. Поля оружия (градусы)

| Поле | Смысл | M4 | AK-47 | M249 | SVD |
|------|--------|----|-------|------|-----|
| `VerticalRecoil` | подъём за выстрел до множителей | 0.09 | 0.14 | 0.07 | 0.16 |
| `HorizontalRecoil` | боковой kick до паттерна | 0.035 | 0.075 | 0.09 | 0.04 |
| `RecoilRecoveryPerSecond` | возврат offset, °/с | 0.70 | 0.55 | 0.85 | 0.50 |
| `RecoilPatternSeed` | фаза синуса (плюс хэш имени/экземпляра) | ~1.57 | ~3.13 | ~7.82 | ~4.53 |
| `RecoilPerShot` | **legacy, не читается gameplay** | старые 0.4…1.8 | | | |

LMG: меньше вертикаль, больше горизонталь, чуть выше recovery. HMG/MK19: оба kick крупнее, recovery ниже.

Модули и патроны: `RecoilModifier` — множитель **kick**, не конуса.

## 5. Выбор режима Auto (важно)

После удаления отдачи из `θ` нельзя оценивать FullAuto по одному только конусу: intrinsic `θ` маленький, и ИИ решил бы, что авто точно на любой дистанции.

Селектор считает **групповой** диаметр на представительном выстреле:

```
представитель: FullAuto → выстрел 5, Burst → выстрел 3, Semi → 1

predicted = |Offset| после (представитель − 1) kick'ов
            с recovery ×0.7 между ними на RPM оружия
            (без навыка/позы, с модулями)

groupθ      = θ_intrinsic + predicted
groupDiameter = 2 × d × tan(groupθ × π/180)

приемлемо, если groupDiameter ≤ 0.60 / √0.60 ≈ 0.775 м
```

Порядок кандидатов при `FireMode = Auto`: FullAuto → Burst → SemiAuto. При `AimMode = Auto`: Snap → Quick → Full.

Fire discipline по-прежнему режет длину очереди и ставит паузы; на паузе offset **не** сбрасывается, только восстанавливается.

## 6. Кто разрешает выстрел

Коротко, без смены относительно предыдущей модели:

- ready / видимая цель / линия огня;
- RPM (`NextAllowedShotTime`);
- порог `AimProgress` (для авто/burst — в основном 1-й выстрел волны);
- визуальный ствол в допуске (barrel-alignment): visual punch может **отложить** следующий выстрел, не смещая hitscan.

Счётчик `ConsecutiveBurstShotsFired` — для гейта прицела и длины Burst. Он **сбрасывается** на `StopFiring`. `RecoilShotIndex` при этом **не** сбрасывается.

---

## 7. Паузы дисциплины и смена оружия

| Событие | Gameplay Offset | RecoilShotIndex | Visual punch |
|---------|-----------------|-----------------|--------------|
| Пауза очереди / `StopFiring` | recovery идёт дальше | сохраняется | обычно snap в 0 |
| Смена магазина, пока оружие в руках | сохраняется | сохраняется | свой цикл |
| Снятие оружия / `TransientState.Clear()` | `(0,0)` | 0 | 0 |

Именно поэтому короткая пауза «2–3 выстрела — пауза — ещё 2» не начинает очередь с нуля: ствол уже чуть поднят.

## 8. Визуал (не формула пули)

Punch (за выстрел):

```
visualImpulse ≈ deltaY / VerticalRecoil     // ≈ verticalVariation × m
impulse       = visualImpulse × VisualRecoilKickScale
punchPitch    = impulse × ShotPitch(2.5°)
+ translation back/up по тем же правилам, что раньше
```

Climb (каждый кадр):

```
climbPitch = Offset.y × VisualOffsetScale × VisualRecoilKickScale
```

Кривая `PitchCurve(P)` на компоненте больше не кормит climb. Поле оставлено на префабе.

Hitscan **не** берёт visual punch в направление луча, если есть цель.

## 9. Числовой пример: M4 FullAuto, 600 RPM, нейтральные множители

Допущения: `m = AutoRecoilMultiplier = 1.22`, патрон/модули/навык = 1, `VerticalRecoil = 0.09`, `HorizontalRecoil = 0.035`, recovery 0.70 °/с, while-firing ×0.7 → 0.49 °/с. Интервал выстрела `60/600 = 0.10 с`. Recovery между выстрелами ≈ `0.049°`.

Вариация и паттерн зависят от seed; ниже порядок величины при `verticalVariation = 1.0`, `pattern ≈ +0.4`.

```
kickY ≈ 0.09 × 1.0 × 1.22 = 0.110°
kickX ≈ 0.035 × 0.4 × 1.22 = 0.017°
нетто за интервал ≈ 0.110 − 0.049 = 0.061° вверх
```

| Выстрел | Offset до луча (примерно) | Что делает пуля | Offset после kick |
|---------|---------------------------|-----------------|-------------------|
| 1 | (0, 0) | в точку прицеливания + tiny cone | ≈ (0.02, 0.11) |
| 2 | ≈ (0.02, 0.06) после recovery | чуть выше и в сторону | ≈ (0.04, 0.17) |
| 5 | ≈ 0.24° вверх | группа уже выше центра цели | растёт дальше |
| пауза 0.4 с | recovery 0.49×0.4≈0.20° к нулю | следующая пуля не с нуля | не snap |

На 100 м `0.24°` — это ≈ 0.42 м выше точки прицеливания. Конус `θ ≈ 0.2°` даёт пятно диаметра ≈ 0.70 м **вокруг этого смещённого центра**, а не облако на полметра вокруг исходного прицела.

Старая модель на 5-м выстреле раздувала `θ` через `P × 0.22` до нескольких градусов — соседние пули были независимыми семплами огромного конуса. Этого больше нет.

## 10. Что крутить

| Хочу | Крутить | Не крутить |
|------|---------|------------|
| Круче/мягче подъём очереди | `VerticalRecoil`, `AutoRecoilMultiplier` | `BaseShotDispersion` |
| Шире/уже «змейка» в стороны | `HorizontalRecoil`, `RecoilPatternSeed` | конус `θ` |
| Быстрее опускается после паузы | `RecoilRecoveryPerSecond` | `StopFiring` (он больше не snap'ает offset) |
| Кучнее первая пуля | `BaseShotDispersion`, поза, прицел | recoil-поля |
| ИИ реже берёт FullAuto на дистанции | `VerticalRecoil` / recovery (через predicted Offset) или порог 0.775 м | надеяться, что конус «сам раздует авто» |
| Сильнее картинка kick | `VisualRecoilKickScale`, `ShotPitch` | gameplay offset |
| Меньше отдача у бойца | RecoilControl (kick вниз, recovery вверх) | FullAuto control-blend 5…10 — его нет |

Стартовые ассеты — калибровочная точка, не финал баланса. Если очередь «не поднимается»: recovery слишком большой относительно `VerticalRecoil × RPM`. Если улетает в зенит: мало recovery или велик `VerticalRecoil` (кап 12° всё равно поймает).

## 11. Чего больше нет

- `EquippedWeaponTransientState.RecoilPenalty` / `SetRecoilPenalty`
- `θ × (1 + P × RecoilSpreadScale)` (hitscan 0.22 и контроллер 0.15)
- процедурный паттерн `P × 0.09°` только для авто с `i ≥ 2`
- FullAuto «control blend» выстрелы 5…10 (вертикаль режется, yaw растёт)
- snap gameplay recoil на `StopFiring`
- `AutoSpreadMultiplier` и `GetAutoBurstSpreadMultiplier` в формуле пули
- компенсация прицела стрелком (`ShooterControl`) — отдельный будущий слой
- rigidbody / пружины / таблица 30 точек паттерна
- смешивание visual punch в hitscan

Навык по-прежнему вешается на kick (`GetRecoilAddedMultiplier`) и recovery (`GetRecoilRecoveryMultiplier`). Отдельной ветки «после 5-го выстрела вертикаль в горизонталь» нет.

## 12. Полный каталог: что влияет на точность и отдачу

Ниже — **все** множители, которые сейчас реально входят в пулю. Если источника нет на юните, множитель = 1 (кроме позы: fallback см. §13).

Два независимых канала:

```
θ  = intrinsic-конус     // точность, случайный семпл вокруг центра
центр = aim + lead + Offset   // отдача, детерминированный поворот
пуля  = случайная точка в конусе θ вокруг центра
```

### 12.1. Точность — формула `θ` целиком

```
raw = BaseShotDispersion                    // поле оружия, типично 0.40…0.70
    × ammo.SpreadModifier                   // патрон, типично 1.0 (5.45 ≈ 0.96 не здесь — RecoilModifier патрона в отдачу)
    × GetDistanceDispersionMultiplier(d)    // кривая оружия 0…500 м
    × ∏ attachment.GetDistanceDispersion(d) // оптика ИСКЛЮЧАЕТСЯ в HipFire / PointAim / PreAim
    × postureSpread                         // §13: стойка×движение ИЛИ спринт
    × skill.Marksmanship                    // 0 → ×1.25, 50 → ×1.00, 100 → ×0.75
    × traits.MarksmanshipModifier           // множитель = max(0.01, 1 − modifier)
    × condition.dispersion                  // раны/боль/подавление/усталость ready
    × incompleteAim(progress, d)            // только 1-й выстрел Burst/FullAuto
    × poseSpread                            // HipFire 2.5 / PointAim 1.5 / PreAim 1.75 / Aiming 1
    × poseDistanceCurve(pose, d)            // HipFire на 25 м уже ×3.5
    × laserPointAimSpread(d)                // только PointAim, только ЛЦУ
    × BaseSpreadToDegrees                   // 0.35 на hitscan-компоненте

θ = clamp(raw, 0.04°, 12°)
диаметр_пятна_м = 2 × d × tan(θ × π/180)
```

**Не входит в `θ` (это отдача, не точность):** VerticalRecoil, HorizontalRecoil, Offset, RecoilControl, RecoilModifier патрона/модуля, Semi/Auto recoil multipliers, recovery, stance recoil multipliers.

### 12.2. Неполный прицел (только конус)

Пороги прогресса: Snap 0.35, Quick 0.68, Full 1.00.

Базовый множитель от прогресса (до дистанции):

| AimProgress | множитель |
|-------------|-----------|
| 0.00 | 3.00 |
| 0.35 (Snap) | 2.20 |
| 0.68 (Quick) | 1.45 |
| 0.85 | 1.15 |
| 1.00 | 1.00 |

Дистанция масштабирует **избыток** (то, что больше 1):

```
если base ≤ 1: результат = 1
иначе: 1 + (base − 1) × scale(d)

scale: d≤10 → 0.60; 25 → 1.00; 50 → 1.25; ≥100 → 1.50
(внутри формулы d сначала умножается на 0.2: «25 м» в таблице scale — это 125 м реальных)
```

В Burst/FullAuto со 2-го выстрела прогресс для разброса форсируется в 1. Первый выстрел серии может быть широким.

### 12.3. Навык (Marksmanship / RecoilControl)

Шкала 0…100, нейтраль 50 = lerp(худший, лучший, 0.5) = 1.0.

| Навык | Канал | 0 | 50 | 100 |
|-------|--------|---|----|-----|
| Marksmanship | `θ` | ×1.25 | ×1.00 | ×0.75 |
| WeaponHandling | время прицела (не пуля) | ×1.25 | ×1.00 | ×0.75 |
| RecoilControl | kick `m` | ×1.20 | ×1.00 | ×0.80 |
| RecoilControl | recovery °/с | ×0.80 | ×1.00 | ×1.20 |

### 12.4. Индивидуальные черты

`MarksmanshipModifier` / `RecoilControlModifier` — обычно маленькие числа вроде 0.05.

```
dispersion = max(0.01, 1 − MarksmanshipModifier)
recoilKick = max(0.01, 1 − RecoilControlModifier)
recoilRecovery = max(0.01, 1 + RecoilControlModifier)
```

Черта «лучше контроль» одновременно уменьшает kick и ускоряет recovery.

### 12.5. Состояние (раны, боль, подавление, усталость рук)

Флаги по умолчанию выключены. Когда включены, **перемножаются**:

| Флаг | `θ` | kick | recovery |
|------|-----|------|----------|
| Руки ранены | ×1.35 | ×1.25 | ×0.85 |
| Сильная боль | ×1.20 | ×1.10 | ×0.90 |
| Подавление | ×1.15 | — | — |
| Ready-стамина исчерпана | ×1.20 | ×1.50 | — |
| Ноги ранены | не на `θ`; ×1.20 к **времени прицела только на ходу** | — | — |

### 12.6. Патрон

| Поле | Куда |
|------|------|
| `SpreadModifier` | только `θ` |
| `RecoilModifier` | только kick `m` |
| `Velocity` | только упреждение, не конус |
| `ProjectileCount` / дробовой паттерн | несколько лучей вокруг того же центра |

### 12.7. Модули

```
kick:   m *= RecoilModifier × (AutoRecoilModifier если FullAuto/Burst, иначе SemiAutoRecoilModifier)
θ:      только дистанционные кривые модуля; оптика не работает в HipFire/PointAim/PreAim
PointAim + ЛЦУ: отдельный EvaluateLaserPointAimSpread(d)
время прицела: AimTimeModifier × кривая (не пуля, но влияет, успеет ли AimProgress дойти до порога)
```

Компенсатор/ДТК, которые крутили старый `P`, теперь крутят **градусный kick**. Их числа 0.92 / 1.08 всё ещё имеют смысл как «на 8% меньше/больше импульса», но абсолютный эффект другой, потому что единица уже градусы. **Это пункт на переработку (§14.4).**

### 12.8. Отдача — формула kick целиком

```
m = fireModeMult                          // Semi 0.74…0.90 или Auto 1.0…1.45
  × ammo.RecoilModifier
  × ∏ attachment.GetRecoilModifier(mode)
  × RecoilControl_added                   // §12.3
  × traits_recoil                         // §12.4
  × condition_recoil                      // §12.5
  × stanceCombat.recoil                   // §13, таблица стойка×движение

Kick.y = clamp(VerticalRecoil × variation(0.85…1.15) × m,  0,  VerticalRecoil × 1.20 × m)
Kick.x = clamp(HorizontalRecoil × pattern(−1…1) × m,  ±HorizontalRecoil × 1.25 × m)

Offset += Kick
|Offset| ≤ 12°
```

Recovery каждый кадр:

```
rate = RecoilRecoveryPerSecond            // °/с с ассета
     × (курок зажат ? 0.70 : 1.00)
     × (оружие не ready ? 1.20 : 1.00)
     × RecoilControl_recovery
     × traits_recovery
     × condition_recovery

Offset = MoveTowards(Offset, 0, rate × dt)
```

**Стойка и движение входят в kick, но не в recovery** (кроме «не ready»). Спринт не имеет отдельного recoil-множителя — берётся walk standing ×1.25, тогда как конус в спринте ×2.0. Это дыра, см. §14.2.

### 12.9. Что влияет косвенно (не в формуле пули, но в «попал / не выстрелил»)

| Механика | Эффект |
|----------|--------|
| AimProgress / дисциплина | может запретить 1-й выстрел серии |
| Barrel-alignment gate | визуальный ствол vs цель; punch + climb от Offset.y могут задержать следующий выстрел |
| RPM / NextAllowedShotTime | recovery между пулями = rate × (60/RPM) |
| Пауза дисциплины → StopFiring | visual punch snap; Offset **не** snap, только recovery |
| Смена оружия / Clear() | Offset = 0, ShotIndex = 0 |
| Выбор Auto fire/aim | сравнивает `2×d×tan(θ + |predicted Offset|)` с 0.775 м |

## 13. Позы, стойка, движение — что происходит сейчас

Юнит имеет **три ортогональных состояния**, которые путают, если смешать:

1. **Поза оружия** (HipFire / PointAim / Aiming / PreAim / HighReady / NotReady) — как держат ствол.
2. **Стойка тела** (Standing / Crouch / Prone) — анимация ног/корпуса.
3. **Движение** (стоит / есть move intent / спринт).

Они умножаются отдельно. Пример: HipFire + шаг стоя = poseSpread 2.5 × walkStandingSpread 1.25 × HipFire distance curve.

### 13.1. Поза оружия → только `θ` (не kick)

База (пока кэш позы валиден; иначе те же числа как fallback):

| Поза | poseSpread | кривая точности по дистанции (выжимка) |
|------|------------|----------------------------------------|
| Aiming | 1.00 | 25 м ×1.00; 100 м ×1.05; 500 м ×1.15 |
| PointAim | 1.50 | 25 м ×1.20; 100 м ×1.90; 500 м ×7.00 + ЛЦУ |
| PreAim | 1.75 | как Aiming-кривая |
| HipFire / HipFireWalk / HipFireCrouchWalk | 2.50 | 5 м ×1.10; 10 м ×1.50; 25 м ×3.50; 100 м ×10 |
| HighReady / NotReady / LowReady | 1.00 (default ветка) | выстрел из HighReady обычно запрещён порогом прицела |

HipFire на 25 м: `θ` уже в ~3.5 раза шире Aiming **до** стойки. Это было задумано под старый огромный конус с `P`. Под маленьким intrinsic `θ` HipFire на 25 м всё ещё очень широкий (десятые доли градуса × 3.5 × 2.5). **Проверить в Play, не слишком ли.** Пункт §14.3.

Kick **не** зависит от позы оружия. HipFire и Aiming получают одинаковый VerticalRecoil. Разница только в конусе и в допуске ствола (гейт).

### 13.2. Стойка × движение → и `θ`, и kick

Если на юните есть компонент стойки (на пехотном префабе есть), hitscan **не** использует свои поля Standing/Crouch/Prone/Moving. Берётся эта таблица:

| Состояние | `θ` (spread) | kick (recoil) | время прицела |
|-----------|--------------|---------------|---------------|
| Стоя на месте | ×1.00 | ×1.00 | ×1.00 |
| Сидя / лёжа на месте | ×0.92 | ×0.95 | ×1.10 |
| Шаг стоя | ×1.25 | ×1.25 | ×1.55 |
| Шаг сидя / ползок | ×1.12 | ×1.10 | ×1.30 |
| Тащит раненого | ×1.04 | ×1.05 | ×1.10 |
| **Спринт** | ×2.00 (отдельное поле hitscan, обходит таблицу выше) | как «шаг стоя» ×1.25, если move intent ещё есть | прицел обычно не успевает |

**Лёжа = сидя.** Отдельных prone-чисел в боевой таблице стойки нет. На hitscan ещё висят старые поля Crouch 0.90 / Prone 0.75 / Moving 1.35, но они живы только если компонента стойки нет.

Движение = «есть move intent у нав-драйвера», не фактическая скорость. Юнит, который «хочет идти», но стоит в толпе, уже получает walk-штраф.

### 13.3. Что чувствует стрелок в типичных сценах

**Aiming, стоя, очередь M4, 50 м.**  
Конус крошечный. Очередь уходит вверх цельным следом (`Offset.y` растёт ~0.06° за выстрел нетто). Попадания кучные, но выше точки прицеливания. Компенсации прицела нет — стрелок не «тянет вниз».

**HipFire, шаг, 15 м.**  
Конус: 2.5 × ~2.2 (кривая HipFire) × 1.25 (шаг) ≈ ×6.9 к базе. Offset тот же, что в Aiming. Группа широкая **и** её центр ползёт. Раньше `P` ещё сильнее раздувал конус — сейчас ширина почти только от позы.

**Пауза дисциплины 0.4 с после 3 выстрелов.**  
Раньше `P` обнулялся → следующая очередь с нуля. Сейчас Offset за 0.4 с возвращается на `0.49 °/с × 0.4 ≈ 0.20°`. Если накопилось 0.25°, остаток 0.05° — почти с нуля. Если LMG настрелял 2°, остаток ~1.8° — очередь продолжает с поднятого ствола. **Дисциплина больше не «сбрасывает отдачу».** Это главное поведение, которое надо решить в §14.1: так и задумано (реализм) или пауза должна ускорять recovery / частично сбрасывать Offset.

**Спринт-огонь (если гейт пускает).**  
Конус ×2, kick как шаг ×1.25. Ствол визуально дёргается, допуск HipFire moving 16–18°. Gameplay Offset растёт почти как на шаге. Несогласованно.

### 13.4. Визуал vs пуля в позах

Climb = `Offset.y × VisualOffsetScale × VisualRecoilKickScale`. Punch — импульс за выстрел.

Допуск ствола до выстрела (гейт, не конус):

| Поза × стойка × движение | допуск ° |
|--------------------------|----------|
| Aiming стоит | 3 |
| Aiming идёт | 8 |
| Aiming сидя стоит / идёт | 9 / 9 |
| PointAim стоит / идёт | 5 / 10 |
| PointAim сидя стоит / идёт | 7 / 11 |
| HipFire стоит / идёт | 12 / 16 |
| HipFire сидя стоит / идёт | 14 / 18 |

После очереди Offset.y может быть 0.5–3°. Climb держит ствол выше точки прицеливания. Punch snap на StopFiring, climb **нет** (он читает Offset каждый кадр). Гейт может ждать, пока recovery опустит Offset, даже если курок уже отпущен и снова нажат. На Aiming 3° потолок гейта; 2° остаточного Offset уже близко к отказу. **§14.5.**

## 14. Системы на переработку

Метка **НА ПЕРЕРАБОТКУ**. Каждая карточка самодостаточна: зачем, что сломано после смены модели, что считать готовым. По этому разделу можно составить план, не открывая код.

Общий принцип новой модели, от которого пляшем:

> Точность = узкий случайный конус.  
> Отдача = накопленный угол Offset.  
> Соседние пули родственники.  
> Пауза = recovery, не snap (пока не решим иначе).  
> Поза и движение могут менять **и** конус, **и** kick, но это должны быть сознательные разные рычаги.

### 14.1. Fire discipline (паузы очереди) — НА ПЕРЕРАБОТКУ — высокий приоритет

**Зачем система была:** короткие очереди 2–4 + пауза, чтобы `P` успевал откатиться и следующая очередь снова была кучной. Snap `P=0` на StopFiring делал паузу «кнопкой сброса отдачи».

**Что стало:** StopFiring больше не трогает Offset. Пауза 0.3–0.5 с при recovery 0.5–0.85 °/с снимает 0.15–0.40°. Для винтовки после 3 выстрелов (~0.25° накопления) этого хватает почти до нуля. Для пулемёта после 10 выстрелов (~1°+) пауза почти ничего не даёт.

**Решение нужно выбрать явно (не чинить «как получится»):**

- **A. Реализм.** Пауза только recovery. Тогда дисциплина должна стать длиннее на LMG / короче на M4, либо recovery LMG выше. Пересчитать таблицы длины очереди и паузы под °/с, не под старые единицы P.
- **B. Геймплейный сброс.** На паузе дисциплины ускорить recovery (например ×3) или сбросить долю Offset (например 50%), не трогая ShotIndex (паттерн змейки продолжается).
- **C. Сброс Offset, сохранение ShotIndex.** Как старый snap по величине, но горизонтальный паттерн не прыгает на начало синуса.

Пока не выбрано A/B/C, балансить длину очереди бессмысленно: одно и то же число паузы означает разное для M4 и PKM.

**Критерий готовности:** на 50 м M4 после паузы 0.4 с 4-я пуля либо почти в точку прицеливания (если выбрали сброс), либо заметно выше на оговорённые X см (если реализм). Записать выбранный вариант в этот документ.

### 14.2. Стойка × движение × спринт — НА ПЕРЕРАБОТКУ — высокий приоритет

**Зачем:** штраф за шаг и бонус за укрытие.

**Что сломано:**

1. Таблица писалась под `P` (безразмерный штраф). Kick теперь в градусах: ×1.25 на шаге увеличивает **угол очереди на 25%**, не «чуть больше облако». На 8 выстрелах это уже заметный метр на 100 м.
2. **Лёжа = сидя** (×0.92 / ×0.95). Для prone нет отдельной строки. Старое hitscan-поле Prone ×0.75 мёртвое.
3. **Спринт:** конус ×2.0, kick как шаг ×1.25. Два канала разъехались.
4. Recovery не зависит от стойки (лёжа очередь опускается с той же скоростью, что стоя).
5. «Движение» = intent, не скорость.

**Что переделать:**

- Новая таблица **только для новой модели**, три колонки на клетку: `θ ×`, `kick ×`, `recovery ×`. Клетки минимум: стоя/сидя/лёжа × стоит/шаг/спринт (+ тащит).
- Решить, должен ли prone сильно резать kick (стабильный упор) или только конус.
- Спринт: либо запрет огня как сейчас через ready, либо явная строка (например θ ×2.5, kick ×1.6, recovery ×0.5).
- Не использовать мёртвые поля hitscan Standing/Crouch/Prone/Moving как второй источник истины — один компонент, одна таблица.

**Критерий:** одно место в дизайне задаёт 9+ клеток; Play: лёжа кучнее стоя, шаг хуже стоя, спринт хуже шага, и это видно и по конусу, и по подъёму очереди.

### 14.3. Позы оружия (HipFire / PointAim / Aiming) — НА ПЕРЕРАБОТКУ — высокий приоритет

**Зачем:** от бедра близко и грязно, PointAim — лазер, Aiming — точный ствол.

**Что сломано:**

1. Поза крутит **только `θ`**. Kick одинаковый. От бедра очередь так же ползёт вверх, просто вокруг более широкого облака. Визуально «неконтролируемая отдача от бедра» теперь не из `P`, а из широкого конуса + тот же Offset.
2. Кривые HipFire по дистанции (×3.5 на 25 м, ×10 на 100 м) калибровались, когда `P` уже давал несколько градусов. Сейчас база `θ` ~0.2°. HipFire 25 м: 0.2 × 2.5 × 3.5 ≈ 1.75° полуугол ≈ 3 м диаметр на 50 м — возможно всё ещё ок для CQB, нужно смотреть.
3. HighReady/NotReady попадают в default poseSpread 1.0, если выстрел каким-то образом прошёл.
4. Pose не даёт recovery-бонуса (упор приклада в Aiming не ускоряет возврат Offset).

**Что переделать:**

- Решить три рычага позы: `θ ×`, `kick ×`, `recovery ×`. Предложение для старта обсуждения (не факт баланса):

| Поза | θ × | kick × | recovery × | смысл |
|------|-----|--------|------------|--------|
| Aiming | 1.0 | 1.0 | 1.0 | упор, контроль |
| PointAim | 1.5 | 1.1 | 0.9 | щека не на прикладе |
| HipFire | 2.5 | 1.35 | 0.7 | нет упора, сильнее выносит |
| PreAim | 1.75 | 1.15 | 0.85 | переход |

- Пересмотреть HipFire-кривую дистанции: она не должна заменять отдачу. На 100 м HipFire и так не должен попадать — хватит ×4…6, не ×10 поверх 2.5.
- Aiming recovery чуть быстрее (упор) — отдельный множитель, не через «не ready ×1.2».

**Критерий:** на 15 м HipFire группа шире Aiming, и её центр уезжает быстрее. На 100 м HipFire почти бесполезен из-за конуса, а не из-за Offset.

### 14.4. Модули (ДТК, сошки, приклад) и Excel — НА ПЕРЕРАБОТКУ — средний приоритет

**Где файл:** `Tools/CombatBalanceParameters.xlsx`.  
**Как обновить после правок ассетов:** `python Tools/export_combat_balance_excel.py`  
**Лист для новых чисел:** **Параметры** (VerticalRecoil, HorizontalRecoil, Recovery °/с, Semi/Auto ×).  
**Лист Отдача:** старая формула `RecoilPerShot` + burst-кривая. Не калибровать. Заменить, когда будет новая таблица.

**Что сломано:**

- `RecoilModifier` 0.90 на ДТК уменьшает kick на 10%. При VerticalRecoil 0.09 это 0.009° за выстрел — на 600 RPM почти не видно. Старые 0.90 писались против `P≈0.5`. Нужна новая шкала: либо модификаторы агрессивнее (0.70), либо ДТК режет только Vertical, сошки режут Vertical+recovery, приклад режет Horizontal.
- Лист «Отдача» и график Mission Prep считали «качество = 1 / накопленный P». Сейчас график использует `|Offset|`, но UI всё ещё подписан как «контроль отдачи». Игроку нужна подпись в градусах или см на 100 м, не абстрактное качество.
- Burst-кривая `AutoBurstSpreadMultiplierByShot` больше не в пуле, но Excel и ассеты её пекут.

### 14.5. Barrel-alignment gate и визуальный climb — НА ПЕРЕРАБОТКУ — средний приоритет

**Зачем:** не стрелять, пока ствол после kick не смотрит в цель (картинка ≠ луч, но гейт смотрит на картинку).

**Что сломано:** climb теперь = Offset.y (геймплейные градусы). Punch snap на StopFiring, climb остаётся. На Aiming допуск 3°. После средней очереди Offset 0.5–1.5° — гейт ещё пускает. После длинной LMG-ленты Offset 4–8° — юнит **молчит**, пока recovery не опустит ствол ниже 3°, даже если ИИ хочет стрелять. Раньше snap `P=0` снимал climb через PitchCurve(0).

**Что переделать:**

- Гейт должен сравнивать ствол с **уже смещённым** aim (aim + Offset), а не с геометрической точкой цели. Иначе система наказывает за честную отдачу.
- Либо climb визуала не равен 1:1 Offset (масштаб), и гейт смотрит только punch.
- Допуски позы (3/8/12°) пересмотреть: они писались под визуальный Punch 2–4°, не под накопленный Offset.

**Критерий:** после паузы M4 сразу может выстрелить; после паузы ПКМ либо ждёт осознанное время, либо стреляет вдоль уже поднятого Offset, и это совпадает с выбранным вариантом 14.1.

### 14.6. Выбор режима Auto (FullAuto / Burst / Semi) — ПРОВЕРИТЬ, возможно готово

Уже считает `θ + |predicted Offset|`. Представитель: 5-й авто / 3-й burst.

Проверить в Play на 80–150 м: M4 не должен брать FullAuto, если группа 5-го выстрела шире 0.775 м. Если берёт — крутить VerticalRecoil/recovery, не конус. Если не берёт даже в упор — predicted Offset завышен (симуляция без навыка, seed без instance hash).

**Критерий:** на 20 м Auto→FullAuto, на 150 м Auto→Semi или Burst. Записать фактические дистанции переключения для M4 и AK.

### 14.7. Навык RecoilControl и «контроль очереди» — НА ПЕРЕРАБОТКУ — низкий/средний

Старый FullAuto blend 5…10 (вертикаль в горизонталь) удалён. RecoilControl сейчас только `m` и recovery. Хороший стрелок меньше подбрасывает и быстрее опускает. Он **не** уводит очередь в сторону сознательно.

Если нужен «опытный удерживает ровнее / тянет вниз» — это будущий слой ShooterControl (компенсация прицела), не возврат blend 5…10. Не смешивать.

Пока ShooterControl нет, RecoilControl 0 vs 100 должен быть заметен: разница kick 1.20 vs 0.80 = 50% разницы угла к 8-му выстрелу. Проверить, хватает ли.

### 14.8. ИИ длины очереди / planner дисциплины — НА ПЕРЕРАБОТКУ — средний

Planner подбирал длину, исходя из раздутого `θ(P)`. Теперь `θ` почти константа, кучность серии = Offset. Planner должен смотреть predicted |Offset| после N выстрелов vs размер цели, а не «диаметр конуса 5-го выстрела» в старых единицах.

Если planner всё ещё читает burst-spread curve или RecoilPenalty — вычистить. Цель: «сколько пуль выпустить, пока центр очереди не уйдёт из грудной клетки».

### 14.9. Турели M2 / MK19 — НА ПЕРЕРАБОТКУ — средний

Тот же Offset. Визуальный kick другой. Стартовые V/H крупные, recovery низкий. Дисциплина и barrel-gate пехоты на турели могут не подходить (нет HipFire, нет «шага»). Отдельная таблица стойки: только «на станке». Excel роли HeavySupport / GrenadeSupport — заглушки, не баланс.

### 14.10. Дробовик Benelli — ПРОВЕРИТЬ

Несколько лучей вокруг **одного** центра Offset. Kick после выстрела тяжёлый (V=0.20). Semi, между выстрелами длинная пауза — recovery успевает. Главное не сломать паттерн дроби: он должен сидеть вокруг Offset, не вокруг старого P-конуса. Проверить осыпь на 15 и 40 м.

### 15.2. Три типа результата (не одно число «отдача»)

**A. Kick одной пули** — `VerticalRecoil` (и фактический kick с Auto/Semi ×). Отвечает: «насколько дёрнуло один выстрел».

**B. Накопленная отдача после серии** — `|Offset|` после **3 / 5 / 8 / 10** выстрелов с recovery **между** выстрелами (while-firing ×0.7). Главный показатель длины контролируемой очереди. Используется в Auto selector (представитель: 5-й выстрел).

**C. Восстановление после паузы** — после **5** выстрелов пауза **0.2 / 0.4 / 0.8 с** при **полном** recovery (StopFiring, без ×0.7). Важно, потому что snap `P=0` больше нет.

| 2 | HorizontalRecoil | поле ассета |

| 10 | \|Offset\| после 5 выстр + 0.8 с | burst + full recovery |

**Смещение центра на дистанции:**

```text
Δм ≈ d × tan(|Offset| × π/180)
```

На **100 м**: **1° ≈ 1.75 м**. Пример: |Offset|=0.5° → ≈0.87 м на 100 м.

**Допущения baseline-симуляции** (одинаковые в C# и Python):

- без модулей, патрона, навыков, позы, состояния;
- режим: FullAuto (или Auto/Burst, если нет авто; иначе Semi);
- seed только из ассета (без instance hash);
- между выстрелами recovery × **0.7** (как `PredictOffsetBeforeShot`);
- на паузе recovery × **1.0** (полная скорость из ассета).

Отчёт в Unity: меню **Polygone → Combat → Report Recoil Balance Metrics (Stage 1)**.

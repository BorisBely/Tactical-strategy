# Пехота — дизайн-документ системы

**Версия:** 1.3  
**Дата:** 29 августа 2026  
 
**Статус:** принципы и архитектура **ЗАМОРОЖЕНЫ**; детали формул и частных правил — **ОТЛОЖЕНЫ** до своего этапа дорожной карты.

**Назначение.** Это канонический дизайн-документ конечной системы пехотного AI и боя. Описывает **что должно получиться**, **как устроены слои**, **какие принципы не нарушаются** и **что сознательно не решается заранее**. Документ самодостаточен для анализа вне репозитория.

**Связь с разработкой.** Рабочая дорожная карта (`Пехота_дорожная_карта.md`) — это backlog реализации. **Каждый открытый этап #N обязан соответствовать этому дизайн-документу.** Если реализация расходится с дизайном — либо меняется реализация, либо сначала обновляется дизайн (явно, с версией), а не «тихо в коде».

## 1. Конечное видение

Игрок и AI используют **одного и того же солдата**: те же лучи, те же правила Track / Aim / Fire, ту же отдачу, ту же дисциплину огня, те же позы и lean. Разница — в **решениях** (задача, RoE, тактика, позиция), а не в отдельном «читерском» боевом контуре.

Конечный результат — тактическая сила, которая:

- **видит и понимает** ситуацию (восприятие, память, звук, доклады);
- **получает задачу** и умеет её менять при сопротивлении;
- **выбирает позицию** (укрытие, маршрут, готовность, lean);
- **ведёт бой** через общий combat executor;
- **адаптируется**, когда первый план не сработал;
- на высоком уровне **командир** распределяет задачи между группами, а planner выбирает **что попытаться сделать**, не как нажать спуск.

Игрок не должен выучить «болванчиков на точках». Противник после отпора **переоценивает** ситуацию и меняет план.

## 2. Центральный цикл

Все слои вращаются вокруг одного цикла:

```text
                 МИССИЯ / ПРИКАЗ
                        ↓
              СИТУАЦИЯ / ЗНАНИЕ
         (Perception + Sound + Reports + Memory)
                        ↓
                    ТАКТИКА
         (State, RoE, Search, Cover, Movement, Group)
                        ↓
                   ПОЗИЦИЯ
         (укрытие, маршрут, exposure, fire lane)
                        ↓
                  ГОТОВНОСТЬ
         (ReadinessState: NotReady … Aim;
          не поза оружия, не G6 Aim/Fire;
          lean / stance — отдельные оси)
                        ↓
                    COMBAT
         (Target, G6, Discipline, Weapon, Hitscan)
                        ↓
                    ACTION
              (выстрел, движение, граната…)
                        ↓
              МИР ИЗМЕНИЛСЯ
                        ↓
                  PERCEPTION
                   (снова)
```

Приказ задаёт **намерение**, но не обязан задавать каждый физический шаг. Локальные решения (укрыться, lean, сменить позу) допустимы в рамках задачи и RoE.

## 3. Три контура (не смешивать)

```text
┌─────────────────────────────────────────────────────────┐
│ PERCEPTION — что солдат знает о мире                    │
│   Vision, Detection, Memory, Identity, Relationship     │
│   Sound, Ally Report → Perception Snapshot              │
│   Не ходит. Не стреляет.                                │
└─────────────────────────────────────────────────────────┘
                        ↓ read-only snapshot
┌─────────────────────────────────────────────────────────┐
│ COMBAT — как солдат стреляет, если разрешено            │
│   TargetSelector → G6 Track/Aim/Fire → Discipline       │
│   → Weapon → Hitscan / Projectile                       │
│   На префабе всегда. Не читает приказы AI.              │
└─────────────────────────────────────────────────────────┘
                        ↑ gates (RoE, CombatIntent)
┌─────────────────────────────────────────────────────────┐
│ TACTICAL AI — задача, намерение, тактика               │
│   UnitAIState, Commands, Hold/Engage, RoE, Search       │
│   Cover, Movement, Group, Adaptive behaviour            │
│   Не жмёт спуск. Компонент не на префабе по умолчанию.  │
└─────────────────────────────────────────────────────────┘
```

### Нерушимые равенства

```text
увидел           ≠  выбран
выбран           ≠  можно целиться
можно целиться   ≠  решение Fire
решение Fire     ≠  выстрел ушёл
разрешена сила   ≠  стрелять
Engage (AI)      ≠  Fire (G6)
Hold (AI)        ≠  выключить Combat (Track остаётся)
ImmediateThreat  ≠  ThreatLevel.High
ImmediateThreat  ≠  Fire
RoE Allow        ≠  Fire
звук             ≠  Observed
звук             ≠  AimPoint
звук             ≠  Fire
доклад           ≠  увидел
AI.EngageTarget  ≠  Combat.SelectedTarget  (#12: наблюдаемый факт, не auto-merge)
```

Диагностика: **первый разрыв цепочки** определяет виновный контур. Не чинить AI ретюном Q или VisionRange.

## 4. Фундамент (уже реализован, FROZEN)

Эти части **не переписываются** ради «умнее AI». Исправления — только при доказанном дефекте тестом.

### 4.1 Восприятие

```text
Physical Visibility → Q (заморожена) → Attention → DetectionProgress
→ Identity → Relationship → Memory → Sound/Report → Snapshot
```

Конверт: глаз **150 м / 120°**; боевой прицел в Aiming **до 300 м / 8°**. Живой hitscan = текущий обзор. Final Perception **PASS 49/0**.

Identity: Unknown / Friendly / Neutral / Hostile — отделена от UnitTeam мира.

### 4.2 Боевой executor

TargetSelector → EngagementDecision (G6) → Fire Discipline → Weapon → Hitscan.  
Три дальности не смешивать: **обзор/hitscan**, **EffectiveRange (урон)**, **WorkingRange (дисциплина очереди)**.

A10 **CLOSED**: RecoilOffset в градусах; θ не зависит от накопленной отдачи.

### 4.3 Тактическая машина (базовая)

Состояния: Idle / Defense / Attack / Search / Retreat / Flee.  
Действие: Hold / Engage → CombatIntent. **Engage ≠ Fire.**

Search (baseline): LastKnown snapshot → Walk → ~15 м → observe → ReturnState.

Команды: IssueCommand → GameCommandService → GameCommandInput → layer 6.4 **CLOSED**.

### 4.4 Ранги и оружие (числа есть, тактика — позже)

Пять рангов (Recruit … Elite) — пресеты навыков на UnitCombatStats.  
Классы оружия и WorkingRange — влияют на дисциплину и урон.  
**Поведенческий слой ранга и тактические роли оружия** — дизайн #15, не текущая реализация.

## 6. Дизайн по слоям (что должно получиться)

### 6.1 #7 — ImmediateThreat и RoE

**Зачем.** SelfDefense без живого ImmediateThreat мёртв. RoE должен различаться на практике.

**Контракт источника (канон #7).**

```text
ImmediateThreat = true  только если ЭТОТ юнит получил подтверждённую враждебную атаку по себе.
ImmediateThreat = false если события нет или TTL истёк.

ImmediateThreat ≠ ThreatLevel.High
Allow ≠ Fire
RoE ≠ TargetSelector
RoE ≠ вызов Fire
Threat не глобальный: атака A не ставит threat на B
```

**Кто выставляет.** Только `ImmediateThreatSource` по событию боя. Perception / Threat math / TargetSelector / UseOfForceEvaluator **не** ставят флаг.

**Источники в #7:**

| ID | Правило | Входит |
|----|---------|--------|
| A | Враг выстрелил, боевая цель выстрела = этот юнит (даже промах) | да |
| B | Hitscan/снаряд попал в `DamageableTarget` этого юнита; атакующий Hostile по UnitTeam | да |
| C | `NotifyHostileAttack(HostileAttack)` — API на будущее | stub |

Геометрический «мимо, но рядом, цель была другой» и взрывы в стороне — **нет**. Дружеский и нейтральный огонь — **нет**. Фильтр Hostile: world `UnitTeam` (Player↔Enemy), не Identity.

**TTL.** `ImmediateThreatDuration` — SerializeField, не каноническое число. Повторная атака обновляет окно. Истечение → false.

**Поведение RoE (матрица уже FROZEN, не ретюнить).**

```text
входящий огонь / попадание
        ↓
ImmediateThreatSource (per-unit + TTL)
        ↓
UseOfForceEvaluator читает bool
        ↓
Allow / Deny Aim и Fire (Track не трогать)
```

ImmediateThreat **не вызывает Fire**. RestrictedDefense / MissionCombat / FullEngagement в этом этапе остаются с текущей матрицей (зоны — не #7).

**Не входит в #7:** suppression, cover, flee-on-fire, squad, sound perception, flank, CQB, weapon roles, слияние AI/combat цели, публикация мира для #8 сверх хуков A/B.

### 6.5 #12 — Цель и огонь

Калибровка **выбора и переключения** цели, не баланс оружия. **CLOSED / FROZEN 26.08.2026** — `Closed/Target_Fire_Calibration.md`. EditMode 18/0. Play 26/0.

### 6.6 #13 — Dynamic Cover

**Принцип:** укрытия **не расставляет дизайнер**. Нет CoverPoint_001.

Классы:

| Класс | Стоя | Присед |
|-------|------|--------|
| Cover A (crouch) | ❌ | ✅ |
| Cover B (standing) | ✅ | ✅ |
| Partial / Corner | частично | частично |

Оценка позиции (факторы, **формула на этапе**): protection, exposure, visibility, fire lane, distance, mission, weapon, movement cost, escape, danger.

**Архитектура производительности (#13 CLOSED / FROZEN — shared cache first):**

```text
NeedCover
  → local Region
  → Shared Spatial Cache (lazy, dedup, GeometryVersion)
  → cheap filter
  → 3–10 кандидатов
  → индивидуальная оценка
```

Не: каждый юнит полный scan мира. Не: кэш «лучшего укрытия».

Emergency cover: под огнём → ближайшее приемлемое → **destination** (не Move; путь — #14).  
Tactical cover: после спасения → лучше? → reposition если `NewScore > Current + SwitchingCost`.  
Бой из укрытия: cover → expose → observe → fire → return → reassess.  
Контракт: `Closed/Dynamic_Cover.md`. **CLOSED / FROZEN 27.08.2026.** EditMode 169/0. Play `CoverIntegration_LAST.txt` 18/0.

### 6.7 #14 — Tactical Movement и Lean

NavMesh = физический путь. Tactical route = путь с меньшим риском.

В городе предпочтение движения **вдоль зданий/укрытий**, если опасно — не обязательная колонна везде: коридор → колонна; открытая зона → рассеивание.

Cover-to-cover: A → short move → B → …, не через открытое поле.

**Lean** — существующая механика (Quick / Smooth / Deep). Подключение:

```text
Tactical decision → Peek/Lean request → lean system
```

Movement lean: движение вдоль стены + lean + контроль угла. **14.8 закрыт.** Tactical LOD (**14.9 закрыт**) задаёт частоту расчёта, не формулу маршрута.

Контракт: `Closed/Tactical_Movement.md`. **CLOSED / FROZEN 27.08.2026.** Destination ≠ Route. Overlay не Move. Evaluator не Move. Production = Normal.

**#14B Readiness** — отдельная ось, не часть #14 route и не `WeaponPoseState`.

```text
NotReady / Patrol / LowReady / HighReady / PreAim / Aim
```

Не заменяет `UnitAIState`, `CombatIntent`, G6, Cover, Movement.  
`Aim` (готовность) ≠ `G6.Aim` ≠ Fire ≠ поза `Aiming`.  
Визуальный контакт (`HostileVisible`) может поднять готовность **сразу в Aim**; промежуточные состояния не обязательны. Разница рангов и уровней — **скорость перехода**, не линейный workflow.  
Звук боя поднимает LowReady / HighReady (ранг), не Aim и не Fire.  
Успокоение — decay + hysteresis, не кадр восприятия.  
HipFire / PointAim / Aiming остаются **позами оружия**, не состояниями Readiness.

Контракт: `Readiness_State.md`. **#14 movement остаётся FROZEN.** #15 не открывать.

### 6.8 #15 — Weapon role и Rank behaviour

**Не открывать, пока не сказано явно.** #14 уже CLOSED / FROZEN. #15 не повод чинить route / cover / urban / exposure / replan: если снайпер идёт слишком близко — правится Weapon Tactical Profile.

**Weapon Role = Preference ≠ Restriction.**

| Роль | Предпочитает | Может нарушить если |
|------|--------------|---------------------|
| Sniper | дистанция, overwatch, стабильная позиция, LOS | приказ игрока, миссия, вынуждение |
| LMG | широкий сектор, support, стабильное укрытие | движение с группой, штурм |
| Rifle | универсальная тактика | — |
| Shotgun / CQB | близко, углы, комнаты, быстрое движение | приказ в дальний сектор |

Оружие влияет на Position, Movement, Cover, Formation slot, Aggression — не только Fire.

**Rank behaviour** — один AI framework, разный competence:

| Ранг | Поведение (наблюдаемое) |
|------|---------------------------|
| Recruit | плохая позиция, медленные решения, лишняя экспозиция, простое CQB |
| Soldier | базовая компетентность |
| Corporal | лучше cover и позиция, понимает приказ |
| Veteran | corner discipline, lean, CQB, смена поз, оружие |
| Elite | быстрая оценка, минимум экспозиции, адаптация |

Не пять разных AI.

### 6.9 #16 — Group и CQB

Group: Leader, Members, Formation, Spacing, Role, Sector.  
Формации: Column, Line, Wedge, Compressed Column; позже CQB Stack.

Лидер задаёт direction / tempo / objective / formation — не Transform-follow каждого.

В контакте формация **может распасться**: cover / fire / move / rear security.

**CQB** — рамка принята, детали **не утверждены** до design cycle #16B:

```text
один вход → stack → последовательный вход → сектор на бойца
```

Не решать заранее: кто какой угол, slice-the-pie, dead space, rear security, вертикальный CQB.

### 6.10 #17–#23 — Adaptive combat

Отдельные понятия: **Threat**, **ImmediateThreat**, **Suppression**, **Wound** — не смешивать.

Under Fire: return fire | cover | move-to-cover — зависит от rank, weapon, distance, cover, mission.

Wound: hit → can fight? → cover/continue или emergency. Не полная медицинская симуляция.

Suppression: снижает risk tolerance, толкает оставаться за cover.

Reposition: только если новая позиция **достаточно лучше** (не ping-pong каждые 2 с).

Adaptive attack:

```text
ATTACK → RESISTANCE → ASSESS → continue | change plan
```

Flank / alternative route, fire & maneuver, grenade как tactical action в ряду Shoot/Move/Suppress/Flank/Withdraw.

### 6.11 #24–#26 — Commander и Planner

Commander: Attack / Defend / Flank / Withdraw / Search / Hold / Capture — **не** «поверни на 13°».

Squad: assault element / support / cover / reserve.

Planner (HTN / GOAP / Utility / BT) **только здесь**. Решает **что попытаться сделать**. Не управляет стрельбой из-за угла.

```text
Decision → Command → State → Execution
```

## 7. Оптимизация (сквозное требование)

Не отдельный этап — обязательство **каждой** фазы.

| Уровень | Частота | Примеры |
|---------|---------|---------|
| Continuous | каждый кадр | movement, weapon, animation, critical combat |
| Fast | часто | perception, target, aim |
| Tactical | по событию | cover eval, reposition |
| Strategic | редко | squad, commander, planner |

Правила: event-driven; local queries; candidate reduction; cache; tactical tick ≠ Update 60 Гц; group sharing геометрии; LOD по дистанции до игрока.
